## 2. Requirements / acceptance criteria
- AC-1: Compiled packaging pipeline builds native binary artifacts using Nuitka for Python modules and go build for Go core.
- AC-2: Automated release gate inspects packaged edition distributions and fails closed if any readable .py source files are present.
- AC-3: Package builder produces CycloneDX or SPDX compliant SBOM, License BOM (LBOM), and cryptographic digital signatures per edition.
- AC-4: Build-time subsystem plug/unplug mechanism allows excluding the worker subsystem from customer edition packages per EAP profile.

## 4. Logic invariants and state model
- All customer edition packages (enterprise, on-prem, saas, oem) contain zero readable .py source files.
- Python compilation converts modules into native C-extensions (.pyd on Windows, .so on Linux).
- Every distribution package contains a verified SBOM, LBOM, and cryptographic checksum manifest.
- Subsystem exclusions cleanly prune designated modules and declare the exclusion in the EAP manifest.
