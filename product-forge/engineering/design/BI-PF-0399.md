## 2. Requirements / acceptance criteria
- AC-1: The Runtime Dependency Compiler (RDC) accepts an EAP manifest, target OS/arch (linux/amd64, linux/arm64, windows/amd64, darwin/arm64), and license profile to produce a deterministic runtime package composition.
- AC-2: The IP-leakage guard fail-closed rejects any composition for customer/commercial editions (enterprise, saas, on-prem, oem) that contains unprotected raw .py source files.
- AC-3: The native Go engine in go/pfcore exposes rdc.compose and rdc.validate_ip ops over the canonical A1 wire seam with full parity.
- AC-4: The sample-runtime-package/ fixture and manifest are generated and verified against the A1 ComponentManifest and SBOM contracts.
- AC-5: A comprehensive automated test suite in test-framework/tests/pipeline/test_a5_rdc.py verifies hermetic resolution, multi-target OS/arch filtering, and IP-leakage prevention.

## 4. Logic invariants and state model
- All customer edition runtime compositions (enterprise, saas, on-prem, oem) contain zero readable .py source files.
- Composition is deterministic: identical EAP + OS/arch + license produces identical runtime composition artifacts and checksums.
- Multi-target resolution maps architectures to exact platform binaries (e.g. .pyd on windows, .so on linux/darwin).
- Subsystem exclusions declared in EAP are strictly honored in runtime composition.
