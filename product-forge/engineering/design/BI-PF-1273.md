## 2. Requirements / acceptance criteria
- AC-1: core.event_bus.emit() delegates to core.events.emit() canonical Go-backed event seam while preserving in-process callback dispatch and caller signature.
- AC-2: core.event_bus.on() provides an in-process subscription shim ensuring existing handlers for all KINDS receive dispatched events with backward-compatible dict envelopes.
- AC-3: core.orchestration_context.route() and build() consume events from the canonical stream while preserving _POLICY action mappings and coordinator escalation rules.
- AC-4: core.ops_phase.py, core.pipeline_capabilities.py, and scripts/dev/parked_review.py operate without regression over the event bus shim.
- AC-5: core.notification_system.py and core.alerts.py maintain identical public API signatures while integrating as transport adapters for notify and email.
- AC-6: All existing unit and contract tests in test-framework/tests/ remain green with 0 unwired or naming violations in wired_audit.

## 3. Scope and non-goals
### In scope
- core/event_bus.py: Delegate emit() to core.events.emit() canonical stream; retain in-process _HANDLERS callback execution.
- core/orchestration_context.py: Maintain deterministic coordinator policy routing and context assembly.
- core/notification_system.py: Act as a notify transport adapter with identical caller signatures.
- core/alerts.py: Act as an email transport adapter with identical caller signatures.
- test-framework/tests/pipeline/test_event_consumers_shims.py: Regression and contract tests covering all consumers and shims.

### Non-goals
- Modifying the public signatures of on(), emit(), recent(), or KINDS in core/event_bus.py.
- Deleting the legacy/frozen dashboard websocket manager (BI-PF-1276).
- Creating new Python files in core/ (edits to existing shipped files only per language rule).

## 4. Logic invariants and state model
- event_bus.emit() never raises an exception to callers under any failure scenario.
- In-process handlers registered with on() are always invoked in registration order for matching event kinds.
- Events emitted via event_bus.emit() appear in the canonical events stream managed by core.events.py.
- Handler failures are isolated so that one failing callback does not abort other subscribers.

## 6. Failure matrix
| Case | Expected behavior | Error code |
|---|---|---|
| In-process handler throws exception | Exception caught and logged; subsequent handlers execute normally | HANDLER_EXEC_ERROR |
| Go core host unavailable during emit | core.events fallback path engages; local JSONL written; emit() succeeds | EMIT_FALLBACK |
| Unknown event kind passed to route() | Falls back to ("log_only", "low", False) default | UNKNOWN_EVENT_KIND |
| Corrupt or empty event in context build | Skipped gracefully; returns empty event list | MALFORMED_EVENT |
