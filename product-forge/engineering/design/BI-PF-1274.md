## 2. Requirements / acceptance criteria
- A client can connect to GET /api/v1/events/stream and receive text/event-stream chunks with valid event headers and JSON payloads.
- Stream accepts since parameter and replays backlog events occurring after since before listening for active events.
- Operators can create and retrieve event subscriptions via POST and GET /api/v1/events/subscriptions with tenant scoping.
- Operators can update subscription state via PATCH and remove subscriptions via DELETE /api/v1/events/subscriptions/{subscription_id}.
- Subscription creation validates required fields (id, transport, event_types) and rejects invalid transport protocols with 400 ApiError.
