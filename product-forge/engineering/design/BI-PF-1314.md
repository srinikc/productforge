## 2. Requirements / acceptance criteria
- Benchmark suite produces repeatable results for each store with recorded baselines
- EXPLAIN(ANALYZE,BUFFERS) capture tooling available and sampling-only in prod
- SLO dashboards/alerts exist for DB/object/cache/queue
- Quota enforcement and degradation switches demonstrated per store

## 3. Scope and non-goals
### In scope
- Slice 1: benchmark CLI + repeatability protocol + versioned baseline artifact schema.
- Slice 2: EXPLAIN(ANALYZE,BUFFERS) capture with read-only role, allowlist, timeout, rollback, redaction, retention, audit, rate/load caps.
- Slice 3: per-store metrics + quota enforcement + bounded degradation with persistent expiry.
- Slice 4: generate SLO rules/dashboard from measured baselines and validate with promtool/Grafana schema checks.
### Non-goals
- No read replicas, partitioning, or region cells (EDP-24).
- No new public API.
- No production EXPLAIN sampling without an explicit switch.

## 4. Logic invariants and state model
- Benchmark labels never include tenant IDs; run timestamp is an unlabeled gauge, not a label.
- Benchmarks use PF_BENCH_DSN with pf_readonly (NOSUPERUSER/NOBYPASSRLS), synthetic t-bench tenant, and deterministic cleanup.
- Missing DSN fails closed unless --allow-skip records BENCH_STORE_SKIPPED as non-success.
- EXPLAIN runs are read-only, allowlisted, timed out, rolled back, redacted, audited, retained, and capped by both probability and per-minute/concurrency budgets.
- Degradation requires owner, reason, expires_at, max_duration<=15m; expiry is reloaded and enforced; renewals are alerted and bounded.
- SLO rules/dashboard are generated only after measured baselines; config references baseline IDs and validation checks drift.

## 8. Security, authz, tenant isolation
- Bench/EXPLAIN DSN must be a read-only role (pf_readonly) with no superuser/bypassrls.
- Benchmark labels exclude tenant IDs, DSNs, and secrets.
- EXPLAIN uses static allowlisted SQL with no bound tenant parameters; output is redacted and access-controlled.
- Degradation/config changes are operator-only; no public API.
- Explain runs are recorded in an audit log with actor, statement label, sample decision, and artifact path; artifacts are access-controlled and retained per config.
- EXPLAIN artifacts are written to access-controlled retention paths with owner/expiry metadata.

## 9. Observability
- Benchmark metrics: edp_bench_p50_ms/p95/p99/errors by bounded group/scenario; last run is edp_bench_last_run_unixtime (no labels).
- Store metrics: edp_store_requests_total, errors, latency histogram, degraded gauge by bounded store label.
- Quota metrics: edp_quota_allowed_total, edp_quota_denials_total{scope,store}.
- SLO rules and dashboard are generated from config/edp-slo.json and validated for drift/schema.

## 10. Performance and scale
- Benchmarks declare warmup, iteration count, concurrency, deterministic seed, outlier policy, and host class.
- EXPLAIN has sample probability <=0.05 plus max_per_minute and max_concurrent load-shed caps.

## 11. Compatibility, migration, rollout, rollback
- Benchmark scheduling and EXPLAIN sampling default off.
- Enable per environment with operator-owned config and runbooks.
- Disable sampling/scheduling and remove rules/dashboard; no schema change.
- Degradation auto-expires; force-expiry command documented.
