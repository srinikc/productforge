## 2. Requirements / acceptance criteria
- Benchmark suite produces repeatable results for each store with recorded baselines
- EXPLAIN(ANALYZE,BUFFERS) capture tooling available and sampling-only in prod
- SLO dashboards/alerts exist for DB/object/cache/queue
- Quota enforcement and degradation switches demonstrated per store

## 3. Scope and non-goals
### In scope
- Slice 1: benchmark CLI, versioned baseline artifacts, Prometheus SLO sink, SLO config/rules/dashboard.
- Slice 2: EXPLAIN(ANALYZE,BUFFERS) sampling capture with read-only role, allowlist, timeout, rollback, and redaction.
- Slice 3: per-store metrics + quota/degradation policy with bounded expiry and alerts.
- Slice 4: measured baselines and evidence for DB/object/cache/queue.
### Non-goals
- No read replicas, partitioning, or region cells (EDP-24).
- No new public API.
- No production EXPLAIN sampling without an explicit switch.

## 4. Logic invariants and state model
- Benchmarks are deterministic, versioned, and tenant-safe; labels never include tenant IDs.
- Benchmarks use PF_BENCH_DSN with a NOSUPERUSER/NOBYPASSRLS read-only role.
- Missing DSN fails closed unless --allow-skip records per-store skipped evidence.
- EXPLAIN ANALYZE is production-sampled at <=0.05, read-only, allowlisted, timed out, rolled back, and redacted.
- Degradation is bounded by max_duration, auto-expires, emits alerts, and never returns a zeroed success.
- SLO thresholds come from a measured baseline with explicit variance tolerance.
- Config is single-source: config/edp-slo.json generates rules/dashboard; config/edp-degradation.json is schema-validated.
- Benchmark runs set app.tenant_id to a synthetic t-bench tenant and assert non-empty RLS-scoped reads.

## 8. Security, authz, tenant isolation
- Bench/EXPLAIN DSN must be a read-only role (pf_readonly) with no superuser/bypassrls.
- Benchmark labels exclude tenant IDs, DSNs, and secrets.
- EXPLAIN uses static allowlisted SQL with no bound tenant parameters; output is redacted and access-controlled.
- Degradation/config changes are operator-only; no public API.
- Explain runs are recorded in an audit log with actor, statement label, sample decision, and artifact path; artifacts are access-controlled and retained per config.

## 9. Observability
- Benchmark metrics: edp_bench_p50_ms, p95, p99, errors, run_timestamp, with bounded group/scenario labels.
- SLO rules are generated from config/edp-slo.json by scripts/dev/gen_edp_slo.py; Grafana rules are generated from the same source.
- Quota metrics: edp_quota_allowed_total, edp_quota_denials_total{scope,store}.
- SLO rules include for-duration, freshness, latency regression, error rate, and degradation expiry alerts.

## 10. Performance and scale
- Benchmark ops and concurrency are explicit CLI flags.
- EXPLAIN sampling is capped and statement_timeout bounded.
- No unbounded scans; baselines capture ops, concurrency, dataset size, host class, and duration.

## 11. Compatibility, migration, rollout, rollback
- Benchmark scheduling and EXPLAIN sampling default off.
- Enable per environment with operator-owned config and runbooks.
- Disable sampling/scheduling and remove rules/dashboard; no schema change.
- Degradation auto-expires; force-expiry command documented.
