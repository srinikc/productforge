## 2. Requirements / acceptance criteria
- The Azure Blob adapter implements datastore.ObjectStore on go/objstorerest and passes the hardened ConformObjectStore suite against the Azurite emulator/mock.
- Capabilities are declared honestly (immutability/legal-hold/versioning/CMK implemented or declared false and fail-closed) and the adapter is dependency-lean (no Azure SDK).
- buildObjectStore() in go/edpsvc/main.go selects the Azure Blob adapter via PF_OBJECT_BACKEND=azure (or azblob) with container, authentication, and endpoint configuration, verified by unit tests.

## 3. Scope and non-goals
### In scope
- Azure Blob datastore.ObjectStore adapter in go/azurestore
- SharedKey, SAS token, and Bearer token authentication via objstorerest.Auth
- Full ConformObjectStore compliance against in-memory mock and Azurite emulator
- Honest capabilities reporting (all optional capabilities declared false)
- edpsvc buildObjectStore runtime wiring for PF_OBJECT_BACKEND=azure/azblob
- Azure Blob qualification and runbook documentation
### Non-goals
- Azure Data Lake Storage Gen2 hierarchical namespace APIs
- Page blobs or Append blobs (only BlockBlob is required for ObjectStore)
- Importing heavyweight azure-sdk-for-go SDK
