## 2. Requirements / acceptance criteria
- edpsvc accepts a per-tenant credential (or a signed tenant claim from a trusted gateway) and derives the tenant from the authenticated principal, never from a client-supplied X-Tenant-Id/query value.
- Per-tenant quotas and concurrency are enforced against the authenticated tenant; rotating a header/query cannot reset or bypass the bucket, and a cross-tenant request is rejected 403.
- Token issuance/rotation/expiry and the trusted-gateway trust boundary are documented, with tests for forged tenant claims, expired credentials and cross-tenant denial.

## 3. Scope and non-goals
### In scope
- Per-tenant authentication for edpsvc data endpoints
- Trusted gateway HMAC-SHA256 signed claim verification
- Hard quota and concurrency isolation bound to authenticated tenant
- Fail-closed 403 rejection of cross-tenant requests
### Non-goals
- External OAuth2 identity provider integration
- PostgreSQL schema changes (RLS remains managed via EDP-09/17)

## 4. Logic invariants and state model
- Tenant identity is derived strictly from authenticated principal/claims in request context, never blindly from client-supplied header/query.
- Cross-tenant access attempts (where client-supplied tenant != authenticated tenant) are rejected with 403 Forbidden.
- Quota and concurrency accounting is bound to the authenticated tenant; changing header/query cannot reset or evade the token bucket.
- Expired or signature-invalid gateway claims are rejected with 401 Unauthorized.

## 8. Security, authz, tenant isolation
Enforces strict trust boundary at edpsvc: gateway HMAC-SHA256 claim verification, constant-time compare against timing attacks, replay bounded by short expiry, cross-tenant fail-closed 403, and hard quota attribution.

## 9. Observability
Metrics: edp_auth_successes_total, edp_auth_failures_total{reason}, edp_cross_tenant_denials_total, edp_quota_denials_total{scope, tenant}.

## 10. Performance and scale
In-memory token hash lookup O(1) and HMAC-SHA256 computation (< 0.1ms per request), zero DB roundtrip on auth check.

## 11. Compatibility, migration, rollout, rollback
Backward compatible: admin token remains fully functional; gateway secret and tenant tokens enabled via env/config.
Unset PF_GATEWAY_SECRET / PF_TENANT_TOKENS to fall back to admin-only auth mode.

## 13. Decisions and amendments
- D-1478-1: Use HMAC-SHA256 compact JWT/claim tokens for trusted gateway claims with zero external dependencies in Go standard library (crypto/hmac, crypto/sha256).
- D-1478-2: Support dual secret verification (PF_GATEWAY_SECRET, PF_GATEWAY_SECRET_OLD) for seamless secret rotation.
- D-1478-3: Reject any request where client-supplied X-Tenant-Id, query tenant, or JSON body tenant contradicts authenticated tenant with 403 Forbidden.
- D-1478-4: Admin token retains authority to act across tenants or for admin endpoints (/admin/*, /metrics).
