## 1. Requirements / acceptance criteria
- Disposition policy: ACCEPTED is not allowed; BLOCKER/MAJOR/MINOR findings must be ACTIONED. DEFERRED is allowed only for NIT, with an existing backlog id and a HIL DISPOSITION_APPROVAL (hil_confirmed, by hil:*, mode, finding sigs). Enforced at Gate 1, Gate 2, merge gate and completion.
- AC verification: item.ac_verification records each AC with PASS/FAIL/PENDING + evidence + verifier; Gate 2 refuses if any AC is missing/FAIL/PENDING; completion re-checks. 2.5 may flag AC gaps but does not certify.
- Final report: scripts/dev/finalize_item.py persists item.final_report with ACs, test results by kind (unit/api/db/logic/go/other, command/result/counts/duration), total time, input/output/cached tokens, cost + cost_source, accepted/deferred with ids, and gate decisions; completion/merge is blocked without it.
- Execution trail show renders AC verification, test results by kind, accepted/deferred dispositions, totals and a final table; tests cover disposition cap/approval, final-report build/persist, test classification, and completion guards.
- Docs/state: config/review-dispositions.json + store-registry entry; REVIEW-GATES-LIFECYCLE documents the approval, AC and final-report contract; language-rule/store/wired checks pass.
