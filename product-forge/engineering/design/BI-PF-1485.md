## 1. Requirements / acceptance criteria
- Re-reviews diff last_reviewed_HEAD..HEAD, include prior findings/dispositions and full-candidate AC evidence, and bind evidence to base/head; a data-only commit does not invalidate the review.
- Design pack: item.design_pack + generated engineering/design/<ID>.md; Gate 1 and precheck validate enforced items (requirements, invariants, contracts, failure matrix, dependencies, security, observability, performance, test matrix, rollout/rollback, decisions).
- Encoding gate: changed source/config/docs must be UTF-8 without BOM, including working-tree/untracked files; generator reads templates BOM-safely.
- Tests cover delta base/prior context, design-pack check/render/config, and encoding BOM; precheck passes; store/registry/doc updates included.

## 3. Logic invariants and state model
- Review candidate key = (item_id, mode, base_commit, head_commit, diff_sha); evidence file is <item>-<diff_sha>.json; collisions resolve by latest at.
- First review is full merge-base..HEAD; subsequent review is last_reviewed_head..HEAD with prior findings/dispositions and full-candidate AC evidence.
- Evidence stores base_sha, head_sha, diff_sha; a data-only/derived commit after the reviewed head is accepted only if the review-relevant diff is empty.
- Reviewer never writes dispositions; core.backlog owns review_dispositions; HIL owns DISPOSITION_APPROVAL.
- Design pack is required for enforced items (T1+) and validated by both Gate 1 and precheck.
- Encoding change-set = committed base..HEAD + index + worktree + untracked; deleted files are skipped; derived/state paths excluded.
- Risk tier: T0/T1 no architect/HIL gates; T2/T3 require 1.5/1/2.5/2. T1 still requires design pack, tests, code review, precheck.
- All gate failures exit non-zero with an explicit reason; no silent pass.
