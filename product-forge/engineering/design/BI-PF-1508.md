## 2. Requirements / acceptance criteria
- GET /admin/backlog/authority?tenant=<tenant> without a bearer returns 401 UNAUTHENTICATED; status precedence is auth-first, so POST without a bearer is 401 and POST with a bearer is 405.
- With a valid PF_ADMIN_TOKEN and tenant, GET /admin/backlog/authority returns 200 with authority=global, next_id from backlog_id_allocations, reservation_scope=global, reservation_count from the DB-maintained counter, tenant, item_scope=tenant, and item_count scoped to that tenant via forced RLS.
- A missing tenant query parameter returns 400 and the handler never queries backlog_items without a tenant.
- Missing migration 0016/0018, a missing global allocation row, DB outage, or query timeout returns 503 with a fixed backlog-authority-unavailable message; never a zeroed 200 or local/Git fallback.
- An E2E test through edpsvc's real mux fails before the route is added and passes after it is wired; the scope guard rejects any new modified path outside the declared affected_files; no PF-GP agent/pipeline or backlog data files are changed.

## 3. Scope and non-goals

## 4. Logic invariants and state model
- backlog_id_allocations.authority='global' is the sole allocation row and stores reservation_count
- DB triggers on backlog_id_reservations maintain reservation_count for every insert/delete, including out-of-band DML
- Reserve no longer increments the counter; idempotent retries do not insert and do not change the counter
- A missing global allocation row returns ErrAuthorityUnavailable -> 503, never a zeroed 200
- backlog_items access is tenant-scoped by app.tenant_id and forced RLS
- The runtime role is pf_app inheriting pf_runtime: NOSUPERUSER, NOBYPASSRLS
- No local JSON/Git fallback in DB mode
- No DB DSN, token, item content, or cross-tenant item counts in the response

## 13. Decisions and amendments
- Use /admin/backlog/authority to avoid the /backlog/{id} catch-all; buildMux is the sole /admin route owner and has no route registry
- Use BacklogStore over the existing pgx pool, not a new store
- Store reservation_count in backlog_id_allocations and maintain it with DB triggers on reservation insert/delete
- Do not increment the counter in Reserve; idempotent retries return the existing block without touching the counter
- Missing allocation row and missing migration/table both map to 503, never a zeroed 200
- Auth runs before method checks: no bearer -> 401; valid bearer + POST -> 405
- Production startup check fails closed; dev logs/metrics non-fatally
- Scope item_count to the requested tenant because pf_app is RLS-enforced
- Return no storage field; labels reservation_scope/item_scope make the response unambiguous
- Endpoint is admin/human diagnostics only; internal callers use the control plane
