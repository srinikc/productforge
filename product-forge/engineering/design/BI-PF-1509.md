## 2. Requirements / acceptance criteria
- GET /admin/backlog/authority?tenant=<tenant> without a bearer returns 401 UNAUTHENTICATED; POST without a bearer is 401 and POST with a bearer is 405.
- With a valid PF_ADMIN_TOKEN and tenant, GET returns 200 with authority=global, next_id, reservation_scope=global, reservation_count, tenant, item_scope=tenant, and tenant-scoped item_count.
- A missing tenant returns 400 and the handler never queries backlog_items without a tenant.
- Missing migration 0016/0018/0019/0020, a missing global allocation row, DB outage, or query timeout returns 503 with a fixed safe message and a low-cardinality reason log; never a zeroed 200 or local/Git fallback.
- An E2E test through the real mux fails before the route and passes after wiring; no PF-GP/backlog data files are changed.

## 8. Security, authz, tenant isolation
- Admin bearer required; PF_ADMIN_TOKEN compared with SHA-256 + crypto/subtle.ConstantTimeCompare in go/edpsvc/main.go::authorized.
- Runtime DB role is pf_app inheriting pf_runtime: NOSUPERUSER, NOBYPASSRLS; evidence go/edpsvc/internal/limits/profile_test.go::TestCheckDBRoleIntegration and engineering/trails/BI-PF-1509-rls-role.txt.
- Authority probes pg_policies for backlog_items tenant_isolation and requires a non-empty app.tenant_id GUC before any count; counter triggers execute as the runtime role with existing DML grants only.
- No DB DSN, token, item content, or cross-tenant item data in response/logs.
- Admin request logs include principal=admin and a redacted source only; never token, DSN, or item content.

## 9. Observability
- Metric names pinned: edp_backlog_authority_startup_ok, edp_backlog_authority_errors_total, edp_backlog_authority_success_timestamp_seconds, edp_backlog_reservation_requests_total, conflicts_total, exhausted_total.
- No tenant label on gauges; tenant is not a metric dimension to avoid cardinality explosion.
- Runbook has detection, triage, escalation, rollback and reconciliation sections; owner platform-oncall.
- edp_backlog_authority_errors_total carries a low-cardinality reason label (migration_missing,row_missing,timeout,db_unavailable,canceled).
- Alert rule on startup_ok=0 for 10m detects never-applied migrations before on-call triage; runbook documents lead time.
- Error-rate alert: rate(edp_backlog_authority_errors_total[10m]) > 0.05 for 5m; startup_ok=0 for 10m.
- Log-based triage: reason_code plus request correlation id; tenant not a metric label.

## 10. Performance and scale
- Authority and Reserve set transaction-local statement_timeout='5s' independently of the caller context.
- Exact tenant backlog_items count is admin-only and bounded by DBTimeout/statement_timeout; it is not a worker hot path; timeout returns 503.
- Global allocation + reservation counter is a single PK row read; no count scan over backlog_id_reservations.
- Timeouts are classified as reason_code=timeout; large-tenant count timeouts are admin diagnostic bounded by statement_timeout/DBTimeout, not treated as a broken DB in triage.

## 11. Compatibility, migration, rollout, rollback
Back up/restore is rehearsed on a scratch DB before deploy; apply migrations with lock_timeout=5s; migrations are idempotent and interrupted-apply recovery is re-run; route deployed after schema checks.
Remove route first, drain/verify no in-flight requests, then run migrations 0020, 0019, 0018 down; no item data change; counter reconstructible from backlog_id_reservations.
