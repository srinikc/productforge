## 4. Logic invariants and state model
- On requires DB/edpsvc; no fallback for scopes listed in PF_BACKLOG_DB_SCOPES.
- Unlisted scopes remain file-authoritative until parity evidence is added.
- File projections remain derived.
- New IDs are globally unique via the allocator.
- Legacy duplicate IDs are preserved only as tenant-scoped historical rows; no new duplicate is accepted.

## 13. Decisions and amendments
- Legacy cross-scope duplicate IDs are preserved by scoped uniqueness; new IDs remain globally unique.
- Schema change is explicitly approved by this design revision.
- Before 0021, take a verified backup; abort on lock/preflight failure; restore from backup if the down migration is refused.
- Backfill writes through edpsvc POST /backlog, so existing auth/audit paths cover every backfilled row.
- Mode precedence is env PF_BACKLOG_DB > config/env-flags.json > on; invalid values raise BACKLOG_DB_MODE_INVALID.
- Parity compares full JSON item data, not counts.
- structure.yml, full-sweep.yml, and pf-gates.yml set PF_BACKLOG_DB=off for file-mode jobs.
