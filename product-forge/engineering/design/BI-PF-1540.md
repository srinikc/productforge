## 2. Requirements / acceptance criteria
- The backlog API exposes an operator-only endpoint to append a MATERIAL_CHANGE decision with mode, reason, HIL confirmation and revision guard, and the item stores it for review_budget.

- Tests cover API auth/validation, decision persistence, accepted reviewed-ancestor delta, and rejection of arbitrary or non-reviewed bases.

## 8. Security, authz, tenant isolation
Operator-only endpoint; HIL actor is fixed by config/review-material-change.json and bound to the authenticated API token, not self-asserted. Item lookup is scope/project-scoped by _scope_project; no tenant header or caller-controlled tenant. HIL actor config is loaded and validated per request; missing/malformed config fails closed. API route requires operator role AND the fixed configured HIL actor bound to the authenticated token.

## 9. Observability
Structured API error envelope; decision append is auditable through item history/trail; budget refusal messages identify mode and count.

## 10. Performance and scale
Allowlist config is read only inside the decisions handler, not on other backlog requests; O(1) append and constant-size file read, target <1ms handler overhead at p95.

## 18. Design delta review contract

- Delta reviews assess **only changed design fields**; the full design is context.
- Prior findings are verified first and not reopened without new evidence.
- New findings outside the delta must be tagged `[OUT_OF_SCOPE]`.
- Any AC/contract/test/control change must update the matching design rows and evidence in the same delta.
- Evidence records `base_sha`, `head_sha`, `design_sha`, changed fields, and `review_scope: delta`.
- Design deltas do not consume the full-review budget; HIL decides after the agreed delta pass.
