## 2. Requirements / acceptance criteria
- AC-1: Tokenize prompts and compile into encrypted asset bundle using AES-256-GCM authenticated cipher with runtime key derivation.
- AC-2: Shipped customer packages contain zero readable system prompt files, failing closed if raw prompts are detected.
- AC-3: In-memory runtime transparent decryption allows agents to consume instructions without disk leakage.

## 4. Logic invariants and state model
- Zero plaintext prompt markdown files exist in customer-facing compiled distribution packages.
- Decryption happens strictly in-memory; zero scratch or temporary plaintext files are created on disk.
- Bundle integrity is authenticated via AES-256-GCM tag; any single-bit tampering fails closed.

## 6. Failure matrix
| Case | Expected behavior | Error code |
|---|---|---|
| Tampered ciphertext payload | AES-256-GCM tag authentication failure; bundle rejected | ERR_TAG_MISMATCH |

| Invalid decryption key supplied | Decryption fails cleanly without crashing process | ERR_INVALID_KEY |
