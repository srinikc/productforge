## 2. Requirements / acceptance criteria
- AC-1: Vector storage adapter implements datastore.MemoryRepository across SQLite (local/PF-SB) and PostgreSQL pgvector (enterprise/PF-PG) backends.
- AC-2: Community edition & PF-SB run zero-dependency local vector store using SQLite without requiring external daemon infrastructure or compiled C extensions.
- AC-3: Enterprise edition & PF-GP SaaS switch to PostgreSQL pgvector with tenant isolation and row-level security enforcement via DSN auto-dispatch.
- AC-4: Shared conformance test suite verifies 8 canonical memory types, 1536-dim vector validation, ACL scoping, and zero cross-tenant leakage across both engines.

## 4. Logic invariants and state model
- Embedding dimension must strictly match 1536.
- Primary key uniqueness on memory_entries(id).
- Strict tenant isolation on all queries (cross-tenant queries return zero records).
- Private memory entries are visible only to authenticated owner.

## 8. Security, authz, tenant isolation

## 9. Observability

## 10. Performance and scale
Pure-Go zero-allocation vector distance calculation and packed binary float serialization for sub-millisecond retrieval.

## 11. Compatibility, migration, rollout, rollback
Opt-in via PF_MEMORY_DSN environment variable
Unset PF_MEMORY_DSN to revert to default PostgreSQL store; SQLite database files can be restored from point-in-time snapshot.
