## 4. Logic invariants and state model
- Provider modularity: AWS and GCP Terraform configurations live in independent root modules (`deploy/plane-a/terraform/aws/` and `deploy/plane-a/terraform/gcp/`), completely decoupled so no cross-cloud credential coupling exists.
- Observability and health probes: Helm templates define standard liveness and readiness probes for core API (`/api/v1/health`), PostgreSQL (`pg_isready -U productforge`), and MinIO (`/minio/health/live`), with Prometheus metrics scraping annotations.
- Provisioning is fully idempotent: rerunning Terraform and Helm with identical variables produces zero duplicate resources.
- Non-destructive rollback (Guardrail 1): Rollbacks execute `helm rollback <release> <revision>` to reinstate prior known-good platform pods without destroying database state.
- Persistent volume protection: PVCs and storage classes enforce `reclaimPolicy: Retain` so underlying disk data is preserved across pod restarts or Helm uninstalls.
- Multi-AZ HA database architecture (Guardrail 2): Cloud deployments configure Multi-AZ managed databases (AWS RDS PostgreSQL Multi-AZ, GCP Cloud SQL HA) with automated failover; bundled single-pod database is restricted to local/air-gapped/dev targets.
- Pre-destroy verification: Any teardown command requires explicit `--force-destroy-with-confirmed-backup` and performs a pre-flight snapshot check before destroying infrastructure.
- Dry-run validation (Guardrail 4): One-click deployer supports `--dry-run` and `--plan` flags that validate Helm templates and run `terraform plan` without making cloud state changes.
- Health-gated completion: Deployer does not declare completion until health probe `/api/v1/health` and database readiness return success within the target SLA (<10 min warm cluster, <25 min cold cluster).

## 7. Dependencies and failure modes
- Cloud provider IAM permissions and Kubernetes API endpoint responsiveness.
- Docker registry availability for container image pulls.

## 8. Security, authz, tenant isolation
- Database passwords and API tokens managed via Kubernetes Secrets, never plaintext in values or state files.
- Non-root container security context (`runAsNonRoot: true`, `readOnlyRootFilesystem: true`).
- Tenant isolation enforced at the database level via row-level security (RLS) schemas.

## 9. Observability
- Emits structured deployment logs with timestamps, stage indicators, and exit codes.
- Diagnostic dump generated on deployment failure.

## 10. Performance and scale
- Warm cluster deployment SLA: platform Helm deployment and health validation completes in under 10 minutes.
- Cold cloud provisioning SLA: end-to-end VPC, managed EKS/GKE, RDS/Cloud SQL HA, and platform deployment completes in under 25 minutes.
- Auto-scaling supported for core API pods via Horizontal Pod Autoscaler (HPA) resource templates.

## 11. Compatibility, migration, rollout, rollback
- Rolling update deployment strategy with `maxSurge: 1` and `maxUnavailable: 0` for zero downtime.
- Non-destructive rollback: Rollback executes `helm rollback <release> <revision>` to reinstate prior known-good platform pods without destroying database state or PVC volumes.
- Teardown safety: Infrastructure deletion requires explicit `--force-destroy-with-confirmed-backup` and verifies snapshot existence prior to teardown.
