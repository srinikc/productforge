## 2. Requirements / acceptance criteria
- AC-1: Post-deployment smoke test runner executes automated health, database connectivity, and core API verification immediately after deployment.
- AC-2: Any failing smoke test assertion automatically triggers instant rollback to prior healthy revision within 30 seconds.
- AC-3: Rollback orchestration records comprehensive failure evidence, diagnostic logs, and incident report in deployment evidence ledger.

## 3. Scope and non-goals
### In scope
- scripts/dev/rollback_orchestrator.py
- core/release_manager.py
- test-framework/tests/deployment/test_rollback_orchestrator.py
### Non-goals
- Executing destructive database drop or truncate operations.
- Disrupting unaffected cluster workloads outside the failing revision.
- Bypassing audit logging on manual admin overrides.

## 4. Logic invariants and state model
- INV-01: Deployment rollback is strictly non-destructive; shared databases and storage are never dropped or truncated.
- INV-02: Blast radius is service-scoped to the failing platform revision without disrupting unrelated workloads.
- INV-03: Rollback completes within 30 seconds upon post-deploy smoke probe failure.
