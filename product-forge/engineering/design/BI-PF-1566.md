## 2. Requirements / acceptance criteria
- AC-1: Standard MemoryRecord schema implemented in Go with strict field validation.
- AC-2: Validates memory kinds against the canonical 6 types (unknown kinds fail closed).
- AC-3: Existing 8 types in core/agent_memory.py map cleanly into the canonical schema using shared config/memory_legacy_mapping.json.
- AC-4: Temporal validity (valid_from, valid_until) is strictly validated.

## 4. Logic invariants and state model
- Every MemoryRecord must have valid UUID v4 id
- tenant_id and project_id must be non-empty matching ^[a-zA-Z0-9_.:-]+$
- valid_from must be strictly earlier than valid_until (valid_from < valid_until)
- superseded_by cannot equal record id (non-self-referencing)
- payload_ref must use an allowed scheme (s3, https, http, gs, file) if specified
- metadata values must be scalar types (string, float64, bool, int64) under 4096 bytes

## 7. Dependencies and failure modes

## 8. Security, authz, tenant isolation
- Strict multi-tenant scoping on every record via tenant_id and project_id validation
- Max payload bounds (1MB content, 50 tags, 50 metadata items, 4096-byte string values) prevent denial-of-service memory exhaustion
- URL parsing rejects malformed or unapproved URI schemes for external payload references
