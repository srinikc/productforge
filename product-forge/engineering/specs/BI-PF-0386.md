# Functional Spec — BI-PF-0386 — PF platform: IP-value assessment of all modules (rewrite-by-value ranking: high-value -> Go/Rust, low-value -> compiled)

## 1. Outcome
IP-value assessment completed across all Product Forge modules: comprehensive ranked inventory, migration priority classification (Tier 1 High-IP -> Go/Rust rewrite, Tier 2 Medium-IP -> Go, Tier 3 Low-IP/Plumbing -> compiled Python stopgap, Tier 4 Tooling -> Python), machine-readable inventory config, harmonized sensitive_roots, and automated contract tests.

## 2. Actors
- platform architect
- security engineer
- release maintainer

## 3. Scope
- docs/PF-MODULE-IP-ASSESSMENT.md
- config/module-ip-inventory.json
- config/language-rule.json
- config/store-registry.json
- scripts/dev/gen_docs_index.py
- test-framework/tests/pipeline/test_module_ip_assessment.py

## 4. Non-goals
- Rewriting all modules into Go immediately (strangler migration over time)
- Changing runtime functionality of existing pipelines

## 5. Assumptions and dependencies
- Shipped roots are core/, api/, and adapters/; scripts/, tests/, config/, and templates/ are classified as tooling/build-time and never shipped.
- Sensitive roots enforce lower edit-growth thresholds on critical components.
- BI-PF-0387
- BI-PF-0388
- BI-PF-0390
- BI-PF-0395

## 6. Domain and glossary
commercial IP protection, module classification, and migration governance

## 7. Functional requirements
### FR-1 — Comprehensive Module IP-Value Assessment Specification
- **priority:** P0
- **source:** BI-PF-0386
- **preconditions:** Delivery baseline BI-PF-0387 is active.
- **trigger:** Platform architecture and migration planning.
- **inputs:** module inventory and codebase analysis
- **outputs:** docs/PF-MODULE-IP-ASSESSMENT.md
- **errors:** Missing module assessment blocks migration planning
- **auth:** architecture / maintainer only
- **idempotency:** Read-only specification
- **data_rules:** 100% of shipped modules classified
- **edge_cases:** Evaluation of shared adapters and helper utilities
- **acceptance:** Given the codebase modules, when assessing IP value, then all platform modules are categorized into Tier 1, Tier 2, Tier 3, and Tier 4 with explicit migration rationale.
- **verification:** test-framework/tests/pipeline/test_module_ip_assessment.py::test_assessment_doc_present_and_complete

### FR-2 — Machine-Readable Module IP Inventory Configuration
- **priority:** P0
- **source:** BI-PF-0386
- **preconditions:** store-registry allows config store additions.
- **trigger:** Precheck, packaging, and policy validation.
- **inputs:** config/module-ip-inventory.json
- **outputs:** structured module classifications
- **errors:** Unregistered store or unparseable JSON fails closed
- **auth:** tooling / policy checker
- **idempotency:** Deterministic lookup
- **data_rules:** Valid schema pf-module-ip-inventory-v1
- **edge_cases:** New modules added to core/ or api/
- **acceptance:** Given the machine-readable inventory, when queried by tooling, then each module's tier rating, rewrite target, and rationale are returned.
- **verification:** test-framework/tests/pipeline/test_module_ip_assessment.py::test_inventory_schema_and_integrity

### FR-3 — Harmonization of Sensitive Roots Configuration
- **priority:** P0
- **source:** BI-PF-0386
- **preconditions:** config/language-rule.json is active.
- **trigger:** Language rule check during PR precheck.
- **inputs:** config/language-rule.json sensitive_roots
- **outputs:** enforced edit-growth bounds
- **errors:** Unclassified sensitive module bypasses policy
- **auth:** precheck gate
- **idempotency:** Pure function validation
- **data_rules:** Sensitive roots match Tier 1 high-value modules
- **edge_cases:** Allowlisted edit exemptions
- **acceptance:** Given sensitive_roots configuration, when evaluating module edits, then Tier 1 components enforce strict edit-growth bounds.
- **verification:** test-framework/tests/pipeline/test_module_ip_assessment.py::test_sensitive_roots_contain_tier1_modules

### FR-4 — Automated Module IP Assessment Contract Tests
- **priority:** P0
- **source:** BI-PF-0386
- **preconditions:** test-framework is installed.
- **trigger:** pytest test execution.
- **inputs:** test suite
- **outputs:** test verification evidence
- **errors:** Test failure blocks merge
- **auth:** CI / precheck
- **idempotency:** Stateless test execution
- **data_rules:** Zero test flakes
- **edge_cases:** Offline test execution mode
- **acceptance:** Given module IP assessment contract tests, when pytest executes, then all contract tests pass cleanly.
- **verification:** pytest test-framework/tests/pipeline/test_module_ip_assessment.py
