# Functional Spec — BI-PF-0387 — PF platform delivery baseline: ONE source for all editions; new shipped/sensitive logic -> Go; existing -> compiled (Nuitka); no raw .py at customer; migrate by value later

## 1. Outcome
Canonical delivery baseline established for all Product Forge editions: one source, new shipped/sensitive logic in Go, existing Python compiled (Nuitka), no raw .py shipped to customers, and migration by value later.

## 2. Actors
- platform maintainer
- release engineer
- customer consumer

## 3. Scope
- docs/PF-DELIVERY-BASELINE.md
- docs/ARCHITECTURE-DECISIONS.md
- test-framework/tests/pipeline/test_delivery_baseline.py

## 4. Non-goals
- Full Python-to-Go rewrite (non-goal / aspiration)
- Per-edition code forks

## 5. Assumptions and dependencies
- Customer deployments strictly ship compiled artifacts (Go binaries + Nuitka compiled Python).
- SaaS edition runs the server-hosted source.
- BI-PF-0388
- BI-PF-0390
- BI-PF-0392

## 6. Domain and glossary
commercial delivery baseline and packaging governance

## 7. Functional requirements
### FR-1 — Canonical Delivery Baseline Specification
- **priority:** P0
- **source:** BI-PF-0387
- **preconditions:** ADR-0001 is accepted.
- **trigger:** Build or release packaging.
- **inputs:** delivery baseline policy
- **outputs:** docs/PF-DELIVERY-BASELINE.md
- **errors:** Missing baseline blocks delivery
- **auth:** tooling / release only
- **idempotency:** Read-only specification
- **data_rules:** One source for all editions
- **edge_cases:** Evaluation of community vs commercial tiers
- **acceptance:** Given the delivery baseline, when reviewing platform architecture, then one-source multi-edition rules and compiled packaging guarantees are formally defined.
- **verification:** test-framework/tests/pipeline/test_delivery_baseline.py::test_baseline_doc_present_and_complete

### FR-2 — Policy and Configuration Enforcement
- **priority:** P0
- **source:** BI-PF-0387
- **preconditions:** config/language-rule.json and core/change_policy.py are active.
- **trigger:** Change classification or precheck gate.
- **inputs:** changed files list
- **outputs:** classification and policy findings
- **errors:** New raw Python in sensitive roots fails closed
- **auth:** precheck gate
- **idempotency:** Pure function analysis
- **data_rules:** Sensitive modules must integrate with Go core
- **edge_cases:** Allowlisted governance modules
- **acceptance:** Given changed files, when language-rule checks run, then new shipped/sensitive Python is blocked unless in Go or compiled.
- **verification:** test-framework/tests/pipeline/test_delivery_baseline.py::test_sensitive_roots_enforce_go_core

### FR-3 — Multi-Edition Packaging Alignment
- **priority:** P0
- **source:** BI-PF-0387
- **preconditions:** core/packaging.py defines EDITIONS.
- **trigger:** Edition package manifest generation.
- **inputs:** target edition id
- **outputs:** edition metadata and tier mapping
- **errors:** Unknown edition or uncompiled customer package rejected
- **auth:** packaging runtime
- **idempotency:** Deterministic lookup
- **data_rules:** All editions map to canonical tiers
- **edge_cases:** OEM and Community distribution kinds
- **acceptance:** Given an edition, when packaging queries edition attributes, then commercial editions require compiled artifacts with no raw .py.
- **verification:** test-framework/tests/pipeline/test_delivery_baseline.py::test_customer_editions_require_compiled_artifacts

### FR-4 — Automated Delivery Baseline Contract Tests

- **source:** BI-PF-0387

- **trigger:** pytest test execution.
- **inputs:** test suite
- **outputs:** test results and evidence
- **errors:** Test failure blocks merge
- **auth:** CI / precheck
- **idempotency:** Stateless test execution
- **data_rules:** Zero test flakes
- **edge_cases:** Offline test execution mode
- **acceptance:** Given delivery baseline contract tests, when pytest executes, then all 5 contract tests pass cleanly.
- **verification:** pytest test-framework/tests/pipeline/test_delivery_baseline.py
