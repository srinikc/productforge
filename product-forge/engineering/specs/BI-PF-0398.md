## 1. Outcome
Product Forge platform A3 build->package->deploy pipeline operational: automated compilation of Python modules via Nuitka into C-extensions, Go core compilation via go build, digital signing and checksum manifest generation, CycloneDX/SPDX SBOM and License BOM (LBOM) emission, fail-closed NO-RAW-.py release gate enforcing zero raw source code in customer editions, build-time subsystem plug/unplug (absorbing BI-PF-0383), and future-proof asset bundling for prompt and UI/UX assets.

## 2. Actors
- platform release maintainer
- security engineer
- enterprise customer operator
- automated CI/CD pipeline agent

## 3. Scope
- core/packaging.py
- core/release.py
- api/routers/packaging.py
- scripts/dev/packaging_check.py
- test-framework/tests/pipeline/test_a3_packaging.py
- config/eap-registry.json

## 4. Non-goals
- Full rewrite of all Python modules into Go immediately (covered under strangler migration in BI-PF-0407)
- Distributing raw Python source in commercial customer editions
- Changing runtime execution behavior of pipeline stages outside packaging and release gating

## 5. Assumptions and dependencies
- Nuitka and Go compilers are invoked when available; mock/dry-run compilation orchestrator handles lightweight test environments.
- Customer editions (enterprise, on-prem, saas, oem) strictly forbid raw .py files; community/dev may retain source if declared.

## 7. Functional requirements
### FR-1 — Concrete A3 Compiled Packaging Orchestration
- **priority:** P0
- **source:** BI-PF-0398
- **preconditions:** Delivery baseline BI-PF-0387 and module IP inventory BI-PF-0386 are active.
- **trigger:** Packaging build execution via API or CLI.
- **inputs:** scope, project, edition, subsystem options
- **outputs:** compiled package distribution structure and updated packaging manifest
- **errors:** Compilation failure or missing required artifacts aborts package build with explicit error.
- **auth:** release maintainer / operator token
- **idempotency:** Repeated build runs overwrite previous build outputs deterministically.
- **data_rules:** All shipped Python modules compiled to C-extensions (.pyd/.so); Go modules compiled to native binaries.
- **edge_cases:** Handling platforms where native C-compiler is absent in CI dry-run environments.
- **acceptance:** Given a build request for an edition, when running A3 packaging, then native binary artifacts are produced with zero readable Python source files.
- **verification:** test-framework/tests/pipeline/test_a3_packaging.py::test_compiled_packaging_orchestration

### FR-2 — Fail-Closed NO-RAW-.py Release Gate
- **priority:** P0
- **source:** BI-PF-0398
- **preconditions:** Packaging output directory or archive is generated.
- **trigger:** Release gate evaluation or precheck execution.
- **inputs:** packaged artifact directory or file manifest
- **outputs:** pass/fail gate verdict with violating file paths if any
- **errors:** Any uncompiled .py file in a customer edition immediately fails closed with UNMET: RAW_PY_IN_SHIPPED_PACKAGE.
- **auth:** pipeline gate authority / fail-closed
- **idempotency:** Read-only inspection of package contents
- **data_rules:** Shipped customer editions (enterprise, on-prem, saas, oem) must contain exactly 0 raw .py files.
- **edge_cases:** Distinguishing between customer editions and community/dev edition.
- **acceptance:** Given a packaged customer edition, when inspected by the NO-RAW-.py gate, then the release is approved only if no raw .py files exist in the distribution.
- **verification:** test-framework/tests/pipeline/test_a3_packaging.py::test_no_raw_py_gate_enforcement

### FR-3 — Automated SBOM, LBOM, and Digital Signing Emission
- **priority:** P0
- **source:** BI-PF-0398
- **preconditions:** Package artifacts successfully assembled.
- **trigger:** Post-build packaging finalization.
- **inputs:** package footprint, dependencies, and signing credentials
- **outputs:** sbom.json, lbom.json, checksums.txt, and detached digital signature
- **errors:** Missing SBOM or invalid signature material blocks package completion.
- **auth:** operator / signing key authority
- **idempotency:** Deterministic SBOM and checksum generation matching artifact bytes.
- **data_rules:** SHA-256 checksums generated for all package files; licenses mapped to SPDX standards.
- **edge_cases:** Graceful handling when GPG key is absent in test environments by recording unsigned status.
- **acceptance:** Given compiled package artifacts, when final packaging runs, then compliant SBOM, LBOM, and checksum manifests are attached.
- **verification:** test-framework/tests/pipeline/test_a3_packaging.py::test_sbom_lbom_and_signing_emission

### FR-4 — Build-Time Subsystem Plug/Unplug (Absorbing BI-PF-0383)
- **priority:** P1
- **source:** BI-PF-0383 / BI-PF-0398
- **preconditions:** Edition profile specifies subsystem inclusion/exclusion list.
- **trigger:** Package composition and module pruning.
- **inputs:** edition profile and subsystem exclusion flags (e.g. exclude_workers)
- **outputs:** pruned package manifest and distribution archive excluding designated subsystem
- **errors:** Attempting to exclude mandatory core subsystems (e.g. licensing or auth) is rejected.
- **auth:** operator / edition configuration
- **idempotency:** Predictable module exclusion based on declarative edition profile.
- **data_rules:** Excluded modules and their dependencies are completely pruned from the compiled archive.
- **edge_cases:** Ensuring orchestrator remains functional when workers are unplugged.
- **acceptance:** Given an edition configured with exclude_workers=True, when packaging completes, then all worker fleet modules are excluded from the distribution package.
- **verification:** test-framework/tests/pipeline/test_a3_packaging.py::test_subsystem_plug_unplug_workers

### FR-5 — Future-Proof Asset Bundle Cataloging
- **priority:** P1
- **source:** BI-PF-0398 / BI-PF-1550-1554
- **preconditions:** EAP schema v1.0 active.
- **trigger:** EAP manifest construction.
- **inputs:** asset bundles (prompt packs, UI/UX tokens, web console)
- **outputs:** EAP manifest containing verified asset bundle records
- **errors:** Tampered or unmanifested asset bundles fail EAP validation.
- **auth:** package orchestrator
- **idempotency:** Deterministic cataloging of non-code asset bundles.
- **data_rules:** Assets carry checksum, format, and destination metadata.
- **edge_cases:** Handling editions that omit optional asset bundles.
- **acceptance:** Given prompt and UI/UX asset bundles, when EAP builds, then all asset bundles are registered and validated alongside code artifacts.
- **verification:** test-framework/tests/pipeline/test_a3_packaging.py::test_asset_bundle_cataloging

## 8. Non-functional requirements
- Performance: Package manifest inspection and NO-RAW-.py scan completes in under 2 seconds.
- Reliability: Fail-closed validation; unknown format, missing SBOM, or exposed source code blocks release.
- Portability: Multi-platform support across Linux (x86_64, aarch64) and Windows (x64).

## 9. Boundary and error catalog
- ERR_RAW_PY_DETECTED: Shipped customer package contains readable .py source files.
- ERR_SBOM_MISSING: Package build failed to emit compliant SBOM or LBOM.
- ERR_SUBSYSTEM_INVALID_EXCLUSION: Attempted to exclude a non-optional core subsystem.
- ERR_CHECKSUM_MISMATCH: Artifact checksum does not match generated manifest.
