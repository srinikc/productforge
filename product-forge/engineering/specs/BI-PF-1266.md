## 7. Functional requirements
### FR-1 — Persist canonical events in PostgreSQL with tenant seq
- **priority:** P0
- **source:** BI-PF-1266
- **preconditions:** Tenant context and DB authority are available.
- **trigger:** A producer emits a canonical event.
- **inputs:** Envelope with event_id, type, payload, tenant.
- **outputs:** Append-only event row with tenant seq.
- **errors:** EVENT_DB_UNAVAILABLE; no file fallback.
- **auth:** Server-resolved tenant; RLS enforced.
- **idempotency:** event_id is unique per authority.
- **data_rules:** Append-only; seq monotonic per tenant.
- **edge_cases:** Retry and duplicate emit.
- **acceptance:** Given a valid tenant and event When it is emitted Then exactly one event row is appended with a monotonic seq.
- **verification:** Design review plus BI-PF-1268 contract tests.

### FR-2 — Store large event payloads as object references
- **priority:** P0
- **source:** BI-PF-1266
- **preconditions:** Payload exceeds the configured inline threshold.
- **trigger:** The event is emitted.
- **inputs:** Payload bytes and content type.
- **outputs:** Object ref, sha256, size and content type in the event row.
- **errors:** EVENT_PAYLOAD_STORE_FAILED; no event commit.
- **auth:** Object store tenant boundary.
- **idempotency:** Reference content is content-addressed by sha256.
- **data_rules:** DB never stores bytes above threshold.
- **edge_cases:** Object store unavailable or hash mismatch.
- **acceptance:** Given an oversized payload When the event is emitted Then it is stored by reference and round-trips with sha256 verification.
- **verification:** Design review plus BI-PF-1268 object-payload tests.

### FR-3 — Dispatch through outbox with at-least-once dedupe
- **priority:** P0
- **source:** BI-PF-1266
- **preconditions:** Event and outbox row committed.
- **trigger:** Dispatcher polls the outbox.
- **inputs:** Outbox row and subscription target.
- **outputs:** Delivered event; deduped by event_id; DLQ on exhaustion.
- **errors:** EVENT_DELIVERY_FAILED; retry then DLQ.
- **auth:** Subscription auth_ref and tenant context.
- **idempotency:** Consumer dedupe key is event_id.
- **data_rules:** Outbox/event transaction is atomic.
- **edge_cases:** Duplicate delivery and dead lettering.
- **acceptance:** Given a committed event When dispatch is retried Then the consumer receives it at least once and dedupes by event_id.
- **verification:** Design review plus BI-PF-1269 dispatcher tests.

## 10. Non-functional requirements
- Cursor reads are deterministic across restarts.
- DB rows remain bounded; large bytes stay in object storage.
- Outbox delivery is at-least-once.

## 11. Data lifecycle
- Append-only event metadata; payload objects follow retention policy; deletion via store contract.

## 12. Compatibility
- Existing core/events.py API and JSONL readers use a read-only projection during migration.

## 13. Rollback behavior
Stop the Go writer first. Keep the last generated JSONL projection read-only with a freshness bound of 5 minutes; if older, mark the read path degraded and do not rebuild from Python. Restore the event authority from PostgreSQL PITR/backup when DB returns, regenerate the projection with the Go tool, verify cursor/outbox parity, then resume. Never let Python write authority.

## 14. Observability
- Event append p95 < 100 ms; error rate >1% for 5 min pages.
- Outbox lag p95 < 30 s; >5 min for 10 min pages.
- DLQ depth >0 pages immediately.
- Cursor read lag p95 < 30 s.
- Object payload store failures >0 for 5 min pages.
- Outbox row count: >50k for 5 min pages; retention age >7 days pages; cleanup job failure pages.
- Projection freshness: generated_at age >300 s for 5 min pages; owner platform-oncall; read path switches to degraded when stale.
