## 7. Functional requirements
### FR-1 — Subscriber registry and dispatcher
- **priority:** P0
- **source:** BI-PF-1269
- **preconditions:** Event authority and outbox are deployed.
- **trigger:** dispatcher pass runs
- **inputs:** subscription rows; events cursor
- **outputs:** delivered/retried/DLQ outcomes
- **errors:** retry then DLQ
- **auth:** tenant-scoped store
- **idempotency:** dedupe by subscription_id,event_id
- **data_rules:** one event store
- **edge_cases:** duplicate delivery
- **acceptance:** Given a matching event, when dispatched, then it is delivered once-effective and failures retry then DLQ.
- **verification:** go test ./... in edpdata

### FR-2 — Single-writer registry
- **priority:** P0
- **source:** BI-PF-1269
- **preconditions:** Event authority and outbox are deployed.
- **trigger:** subscription is upserted
- **inputs:** subscription payload
- **outputs:** persisted subscription
- **errors:** retry then DLQ
- **auth:** tenant-scoped store
- **idempotency:** dedupe by subscription_id,event_id
- **data_rules:** one event store
- **edge_cases:** duplicate delivery
- **acceptance:** Given a subscription, when upserted, then the event store is the only writer and no second event store exists.
- **verification:** go test ./... in edpdata
