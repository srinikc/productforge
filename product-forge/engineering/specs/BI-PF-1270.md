## 7. Functional requirements
### FR-1 — In-process and webhook transports
- **priority:** P0
- **source:** BI-PF-1270
- **preconditions:** Dispatcher and event store are live.
- **trigger:** dispatcher sends an event
- **inputs:** subscription; event
- **outputs:** callback invoked / webhook POST
- **errors:** retry then DLQ
- **auth:** tenant-scoped subscription
- **idempotency:** event_id idempotency key
- **data_rules:** no second event store
- **edge_cases:** missing SMTP; 409 duplicate
- **acceptance:** Given a subscriber, when dispatched via inproc or webhook, then delivery is attempted and failures follow dispatcher retry/DLQ.
- **verification:** go test ./... and API tests

### FR-2 — Notify/email transport and API
- **priority:** P0
- **source:** BI-PF-1270
- **preconditions:** Dispatcher and event store are live.
- **trigger:** dispatcher sends notify event
- **inputs:** event; priority
- **outputs:** in-app notification and optional email
- **errors:** retry then DLQ
- **auth:** tenant-scoped subscription
- **idempotency:** event_id idempotency key
- **data_rules:** no second event store
- **edge_cases:** missing SMTP; 409 duplicate
- **acceptance:** Given a notify event, when delivered, then in-app is stored and email follows the priority gate.
- **verification:** go test ./... and API tests

### FR-3 — Permanent failure classification
- **priority:** P0
- **source:** BI-PF-1270
- **preconditions:** Dispatcher and event store are live.
- **trigger:** transport returns an error
- **inputs:** HTTP status/error
- **outputs:** retry or immediate DLQ
- **errors:** retry then DLQ
- **auth:** tenant-scoped subscription
- **idempotency:** event_id idempotency key
- **data_rules:** no second event store
- **edge_cases:** missing SMTP; 409 duplicate
- **acceptance:** Given a permanent webhook failure, when dispatched, then it goes to DLQ without retry.
- **verification:** go test ./... and API tests

### FR-4 — Security and observability
- **priority:** P0
- **source:** BI-PF-1270
- **preconditions:** Dispatcher and event store are live.
- **trigger:** transport handles a target/secret
- **inputs:** URL; HMAC key
- **outputs:** validated delivery and metrics
- **errors:** retry then DLQ
- **auth:** tenant-scoped subscription
- **idempotency:** event_id idempotency key
- **data_rules:** no second event store
- **edge_cases:** missing SMTP; 409 duplicate
- **acceptance:** Given a target or HMAC key, when validated, then SSRF/secret rules apply and signals are emitted.
- **verification:** go test ./... and API tests
