# Functional Spec — BI-PF-1272 — Eventing SSOT: Python thin-client cutover of core/events.py over the A1 wire seam (edit-only)

- **Version:** 1
- **Status:** approved

## 1. Outcome
Python emitters delegate event emission to the Go core over the A1 wire seam with zero consumer disruption, gaining monotonic sequence numbers and Go event authority.

## 2. Actors
- Python Emitters: Existing pipeline runners, stages, workers, and tasks calling core.events.emit().
- Go Event Core: The authoritative append-only store in go/pfcore managing monotonic sequencing.
- go_host Bridge: The A1 wire contract interface in core/go_host.py invoking pfcore-host.

## 3. Scope
- core/events.py: Edit-only update to emit() delegating to go_host.event_append with fallback.
- test-framework/tests/pipeline/test_events_thin_client.py: Dedicated contract tests.

## 4. Non-goals
- Creating new Python modules or public abstractions.
- Modifying existing caller signatures or removing backwards-compatible envelope fields.
- Altering downstream subscriber transport or notification logic (handled in subsequent items).

## 5. Assumptions and dependencies
- go/pfcore-host binary is compiled or built on-demand by go_host._ensure_binary().
- go_host.event_append() assigns monotonic sequence numbers and writes JSON lines under lock.
- core.contracts
- core.go_host
- go/pfcore

## 6. Domain and glossary
- A1 Wire Seam: JSON-over-stdin/stdout IPC contract between Python runtime and Go native core.
- Monotonic Sequence (seq): Strictly increasing integer assigned to each event by the Go authority.
- Strangler Pattern: Fail-safe mechanism falling back to local Python JSONL append if Go is unreachable.

## 7. Functional requirements
### FR-1 — Go Event Append Delegation
- **priority:** P0
- **source:** BI-PF-1272
- **preconditions:** Event emission requested via core.events.emit().
- **trigger:** Caller invokes emit(project_dir, event_type, ...).
- **inputs:** project_dir; event_type; optional kwargs
- **outputs:** event dictionary with seq assigned by Go core
- **errors:** Go host failure triggers fallback strangler path
- **auth:** tooling only
- **idempotency:** append-only sequence generation
- **data_rules:** valid event envelope with legacy and formal fields
- **edge_cases:** Go host binary missing or compile failure
- **acceptance:** Given an event, when emitted, then Go core assigns monotonic seq and appends.
- **verification:** pytest test-framework/tests/pipeline/test_events_thin_client.py

### FR-2 — Fail-Safe Strangler Fallback
- **priority:** P0
- **source:** BI-PF-1272
- **preconditions:** Go core host unavailable or returns an error response.
- **trigger:** go_host.event_append returns ok=False or raises.
- **inputs:** event dictionary and target file path
- **outputs:** event appended directly to file without crashing caller
- **errors:** suppressed gracefully; never raises to caller
- **auth:** tooling only
- **idempotency:** append-only write
- **data_rules:** legacy JSON line append
- **edge_cases:** read-only filesystem
- **acceptance:** Given Go host unavailable, when emit is called, then event is written directly.
- **verification:** pytest test-framework/tests/pipeline/test_events_thin_client.py

### FR-3 — Public Symbol and Envelope Stability
- **priority:** P0
- **source:** BI-PF-1272
- **preconditions:** Existing 50+ callers invoke core.events functions and constants.
- **trigger:** Module import and invocation.
- **inputs:** TYPES; EVENT_VERSION; path(); read(); counts()
- **outputs:** identical return values and types
- **errors:** none
- **auth:** public module interface
- **idempotency:** pure functions and queries
- **data_rules:** back-compatible dictionary structure
- **edge_cases:** empty project directory
- **acceptance:** Given existing callers, when calling events API, then behavior is unchanged.
- **verification:** pytest test-framework/tests/pipeline/test_api_events.py

## 10. Non-functional requirements
- Emission latency: < 5ms via Go host wire seam.
- Reliability: Zero raised exceptions to pipeline callers (never crash execution).
- Compatibility: 100% backward compatibility for all 50+ callers.

## 11. Data lifecycle
- Events are stored append-only in products/<project>/events.jsonl.
- Monotonic sequence numbers are strictly increasing per event store.

## 12. Compatibility
- 100% backward compatible with legacy JSONL reader and API-5 event envelope.

## 13. Rollback behavior
- Revert edits to core/events.py to restore direct file append immediately.
