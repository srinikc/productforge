# Functional Spec — BI-PF-1273 — Eventing SSOT: migrate existing consumers (event_bus/context/ops/capabilities/parked/notifications/alerts) behind shims

- **Version:** 1
- **Status:** in_progress
- **Owner:** developer
- **Source:** BI-PF-1273
- **Linked design:** engineering/design/BI-PF-1273.md

## 1. Outcome
Existing event consumers across Product Forge (`event_bus`, `orchestration_context`, `ops_phase`, `pipeline_capabilities`, `parked_review`, `notification_system`, and `alerts`) migrate onto the canonical Go-backed event core through compatibility shims, eliminating duplicate event streams and preserving 100% caller stability.

## 2. Actors
- **Event Producers:** Pipeline runners, stages, ops tasks, and capabilities emitting lifecycle signals.
- **In-Process Consumers:** Handlers registered via `event_bus.on(kind, handler)` expecting immediate dispatch.
- **Coordinator Router:** `orchestration_context.route()` mapping runtime anomalies and stuck states to deterministic policies.
- **Transport Adapters:** `notification_system` and `alerts` delivering notifications and email alerts from event bus subscriptions.

## 3. Scope
- `core/event_bus.py`: Cut over `emit()` to route canonical emissions through `core.events.emit()` while retaining in-process `_HANDLERS` dispatch and caller compatibility.
- `core/orchestration_context.py`: Ensure event reading and signal routing align with canonical event structures without breaking `_POLICY`.
- `core/notification_system.py`: Function as a stable notify adapter integrating with the event bus.
- `core/alerts.py`: Function as a stable email transport adapter without breaking `email(...)` signatures.
- `test-framework/tests/pipeline/test_event_consumers_shims.py`: Contract tests covering all consumers and shims.

## 4. Non-goals
- Deleting the legacy/frozen dashboard websocket manager (scheduled for retirement in BI-PF-1276).
- Creating new public external REST/SSE APIs (scoped to BI-PF-1274).
- Creating new Python files in `core/` (edits to existing shipped modules only per language rule).

## 5. Assumptions and dependencies
- `core.events` is cut over as a thin-client over Go event authority (`go_host.event_append`) per BI-PF-1272.
- `core.contracts` maintains the event envelope schema.
- Existing callers of `event_bus.on()`, `emit()`, and `recent()` must experience zero API breakage.

## 6. Domain and glossary
- **Event Bus Shim:** An in-process backward-compatibility layer providing `on()` and `emit()` semantics over the canonical event stream.
- **Canonical Stream:** The single authoritative event stream managed by `core/events.py` and the Go event core.
- **Transport Adapter:** Modular consumer that translates canonical events into specific delivery channels (notify, email).

## 7. Functional requirements

### FR-1 — Canonical Emission via Event Bus
- **priority:** P0
- **source:** BI-PF-1273
- **preconditions:** Caller invokes `core.event_bus.emit(kind, **payload)`.
- **trigger:** Pipeline or task emits a signal.
- **inputs:** `kind: str`, arbitrary payload keyword arguments.
- **outputs:** Dispatched event dictionary conforming to canonical event taxonomy.
- **errors:** Suppressed gracefully; `emit()` never raises an unhandled exception to callers.
- **auth:** Tooling / in-process.
- **idempotency:** Append-only event emission.
- **data_rules:** Includes standard fields (`kind`, `at`, `run_id`, `stage`, `agent`).
- **edge_cases:** Missing project or run context falls back cleanly without error.
- **acceptance:** Emitting through `event_bus.emit()` delegates to `core.events.emit()` and triggers in-process handlers.
- **verification:** `pytest test-framework/tests/pipeline/test_event_consumers_shims.py::test_event_bus_canonical_delegation`

### FR-2 — In-Process Subscription Shim
- **priority:** P0
- **source:** BI-PF-1273
- **preconditions:** Handler registered via `core.event_bus.on(kind, handler)`.
- **trigger:** Matching event emitted via `event_bus.emit()`.
- **inputs:** `kind: str`, `fn: Callable`.
- **outputs:** Callback invocation with the event dict.
- **errors:** Handlers that raise are logged/suppressed so one failing handler does not abort subsequent handlers.
- **auth:** In-process.
- **idempotency:** Handler list preserves registration order.
- **data_rules:** Delivers event dict containing `kind` and payload.
- **edge_cases:** Wildcard subscription `*` receives all kinds.
- **acceptance:** Given a registered callback, when matching event is emitted, then callback receives the event payload.
- **verification:** `pytest test-framework/tests/pipeline/test_event_consumers_shims.py::test_event_bus_handlers`

### FR-3 — Context and Policy Routing Integrity
- **priority:** P0
- **source:** BI-PF-1273
- **preconditions:** Actionable event (`stuck`, `anomaly`, etc.) passed to `orchestration_context.route()`.
- **trigger:** Coordinator evaluates event.
- **inputs:** Event dictionary.
- **outputs:** Deterministic decision dict `{kind, action, priority, escalate, at}`.
- **errors:** Unknown kinds fall back to `("log_only", "low", False)`.
- **auth:** In-process.
- **idempotency:** Pure deterministic function.
- **data_rules:** Preserves `_POLICY` dictionary mappings.
- **edge_cases:** None/empty event returns safe default without crashing.
- **acceptance:** All defined event kinds map to their exact designated policy actions and priority.
- **verification:** `pytest test-framework/tests/pipeline/test_event_consumers_shims.py::test_orchestration_context_routing`

### FR-4 — Notification and Alert Transport Compatibility
- **priority:** P1
- **source:** BI-PF-1273
- **preconditions:** `core.notification_system` and `core.alerts` invoked by callers or event listeners.
- **trigger:** Notification creation or alert dispatch.
- **inputs:** Standard notification / alert parameters.
- **outputs:** Notification record or email dispatch status.
- **errors:** Graceful error handling; fallback when external transports are disabled.
- **auth:** In-process.
- **idempotency:** Deduplicated notification generation.
- **data_rules:** Preserves schema of notification entries.
- **edge_cases:** Missing SMTP / external configuration behaves as no-op.
- **acceptance:** Existing method signatures of `notification_system` and `alerts` remain identical and functional.
- **verification:** `pytest test-framework/tests/pipeline/test_event_consumers_shims.py::test_notifications_alerts_transports`
