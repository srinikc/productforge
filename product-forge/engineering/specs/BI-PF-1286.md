# Functional Specification: BI-PF-1286 — Entitlement Enforcement Across Remaining Execution Boundaries

## 1. Context & Business Need
In A2 (`BI-PF-0396`), asymmetric licensing and entitlement enforcement were wired into the worker job-claim boundary (`core/job_manager.py:427`), checking the base group `build-products`. However, other primary execution boundaries—specifically pipeline stage execution (`core/orchestrator/stage_runner.py`), individual capability invocation (`core/capability_bridge.py`), and gated REST API endpoints (`api/auth.py` / `api/routers/`)—do not yet enforce their specific feature group entitlements.

Without enforcement across these remaining boundaries, a tenant with an unentitled tier (e.g., `trial` or `starter`) could trigger add-on capabilities (such as `content-media`, `ai-agents`, or `advanced-compliance`) if invoked directly outside worker job claim.

## 2. Objective
Extend fail-closed entitlement enforcement to:
1. **Pipeline Stage Execution Boundary (`core/orchestrator/stage_runner.py`)**: Before running any pipeline stage (e.g., `11-marketing` requiring `content-media`), verify tenant entitlement.
2. **Capability Invocation Boundary (`core/capability_bridge.py`)**: Before invoking capability functions (e.g., `build_deck`, `build_video` requiring `content-media`), verify tenant entitlement.
3. **API Endpoint Execution Boundary (`api/auth.py`)**: Provide reusable route guards (`require_feature_group`) rejecting unentitled calls with HTTP 403 `ENTITLEMENT_REFUSED`.
4. **Declarative Configuration Mapping (`config/licensing-tiers.json`)**: Drive all action-to-feature-group mappings declaratively from `action_group_map` in `config/licensing-tiers.json` so no feature-group bindings are hardcoded.

## 3. Acceptance Criteria (DoD)
- **AC-1**: The pipeline stage, capability bridge, and API request execution boundaries enforce their configured feature group entitlements fail-closed.
- **AC-2**: Any action attempting execution on an unentitled tier or unknown tenant is refused with LicenseError or HTTP 403 without partial bypass.
- **AC-3**: Per-action feature group mappings for stages, capabilities, and API endpoints are loaded from config/licensing-tiers.json action_group_map.
- **AC-4**: Automated test coverage in test-framework/tests/pipeline/test_entitlement_boundaries.py proves fail-closed refusal across all three boundaries.

## 4. Execution Boundaries & Mappings
### 4.1 Boundary Matrix
| Boundary | Enforcement Point | Action Identifier | Default Group | Refusal Behavior |
| :--- | :--- | :--- | :--- | :--- |
| **Worker Claim (Existing A2)** | `core/job_manager.py:427` | Job type / project | `build-products` | `claimed: false, reason: entitlement` |
| **Pipeline Stage** | `core/orchestrator/stage_runner.py` | `stage_id` (e.g. `11`) | Mapped via `action_group_map.stages` | Raises `licensing.LicenseError` |
| **Capability Bridge** | `core/capability_bridge.py` | `name` (e.g. `build_video`) | Mapped via `action_group_map.capabilities` | Returns `{"error": "entitlement: ..."}` |
| **API Endpoints** | `api/auth.py:require_feature_group` | Route path / tag | Mapped via `action_group_map.api_routes` | Raises `ApiError(403, "ENTITLEMENT_REFUSED")` |

### 4.2 Group Mappings in `config/licensing-tiers.json`
- `build_deck`, `build_video` -> `content-media` (Add-on, Pro/Enterprise)
- `research_domain`, `compile_knowledge` -> `ideate-design` (Base group, all tiers)
- `byot_catalog`, `godock`, `refresh_catalog` -> `extend-integrate` (Add-on, Starter+)
- `onboard_customer` -> `launch-grow` (Add-on, Enterprise)
- `estimate_costs`, `plan_release` -> `plan-deliver` (Base group, all tiers)
- `validate_code` -> `assure-quality` (Base group, all tiers)

## 5. Security & Fail-Closed Invariants
- Unknown/missing tier: fails closed (`allowed: false`).
- Unknown/unregistered action: defaults to requiring `build-products` or fails closed.
- Operator role: exempt (`effective_tier()` resolves to `enterprise`).
- Tenant mode: tenant's recorded tier is strictly checked against the mapped group.
