# Functional Spec — BI-PF-1531 — EDP: make PostgreSQL backlog authority the default for PF-SB and PF-GP scopes

- **Version:** 1
- **Status:** APPROVED
- **Owner:** engineering
- **Source:** BI-PF-1531 DB authority cutover
- **Functional SHA:** 452b44a11a71
- **Linked design:** engineering/design/BI-PF-1531.md

## 1. Outcome
- PostgreSQL/edpsvc is the default backlog authority for verified scopes; file projections remain rollback/reconcile artifacts.

## 2. Actors
- Backlog worker/agent
- edpsvc
- operator/runbook owner
- HIL approver

## 3. Scope
- DB authority for PF_BACKLOG_DB_SCOPES
- scoped uniqueness migration
- backfill/parity/export
- fail-closed tenant behavior
- CI DB-mode and file-mode isolation

## 4. Non-goals
- No cross-region DR/T4 implementation
- No renumbering of legacy IDs
- No deletion of file projections

## 5. Assumptions and dependencies
- Migrations through 0023 are applied in order
- A verified backup artifact exists before 0021
- edpsvc binds tenant GUC transaction-locally
- BI-PF-1315 EDP-23 backup/PITR
- PostgreSQL 16
- Go edpsvc /backlog
- GitHub Actions

## 6. Domain and glossary
- tenant: tenant_id partition
- scope: product_forge or project
- mode: on/off/dual/shadow
- FR: functional requirement

## 7. Functional requirements
### FR-1 — Default mode resolves on with per-scope authority
- **priority:** Must
- **source:** AC-1
- **preconditions:** Configuration loaded
- **trigger:** Backlog read/write/delete or ID reservation
- **inputs:** PF_BACKLOG_DB; PF_BACKLOG_DB_SCOPES; scope/project
- **outputs:** DB authority for allowlisted scope; file authority otherwise
- **errors:** BACKLOG_DB_MODE_INVALID; BACKLOG_DB_SCOPES_EMPTY
- **auth:** Existing edpsvc admin authorization
- **idempotency:** Mode resolution is pure and repeatable
- **data_rules:** Allowlist key uses project or scope; Case variants are distinct
- **edge_cases:** empty allowlist; invalid mode; unlisted scope
- **acceptance:** Given DB mode on and an allowlisted scope, When backlog is read or written, Then PostgreSQL is authoritative.; Given an empty allowlist, When mode is on, Then startup/operation fails closed.
- **verification:** test_backlog_db_cutover.py and test_backlog_db_authority.py

### FR-2 — DB-mode CI exercises real Postgres path
- **priority:** Must
- **source:** AC-2
- **preconditions:** Postgres service available
- **trigger:** Pull request or manual workflow
- **inputs:** migrations; edpsvc; backfill files
- **outputs:** backlog-db CI job result
- **errors:** job failure on migration/backfill/parity/test failure
- **auth:** GitHub Actions only
- **idempotency:** Workflow reruns are safe
- **data_rules:** CI uses a fresh database
- **edge_cases:** preflight backup artifact missing; 0022 index failure
- **acceptance:** Given the backlog-db workflow, When the job runs, Then it applies 0021/0022, starts edpsvc, backfills, runs parity for both tenants, and runs tests.
- **verification:** test_backlog_db_workflow.py and backlog-db CI

### FR-3 — File/DB parity is scoped and content-complete
- **priority:** Must
- **source:** AC-3
- **preconditions:** Backfill completed
- **trigger:** Parity command
- **inputs:** tenant; file item sources; DB rows
- **outputs:** zero missing/extra/mismatched rows
- **errors:** BACKLOG_DB_PARITY_DRIFT
- **auth:** Operator/admin command
- **idempotency:** Read-only parity
- **data_rules:** Compare full JSON item data; Scan products/*/data/backlog/items
- **edge_cases:** generated-product tenant; empty source with DB rows; numeric normalization
- **acceptance:** Given backfilled PF-SB files, When parity runs for product_forge, Then missing/extra/mismatch are zero.
- **verification:** backlog_db_parity.py and test_parity_scans_products

### FR-4 — Tenant-less DB operations fail closed
- **priority:** Must
- **source:** AC-4
- **preconditions:** DB mode on
- **trigger:** Get/List/Put/Delete call without tenant context
- **inputs:** request tenant; bound GUC
- **outputs:** 503 tenant-context failure
- **errors:** ErrTenantContext mapped to 503; BACKLOG_DB_UNAVAILABLE
- **auth:** Tenant context required
- **idempotency:** No write occurs on failure
- **data_rules:** List/Get/Delete use tenant returned by requireTenant
- **edge_cases:** missing GUC; tenant mismatch; DB unavailable
- **acceptance:** Given no tenant context, When any backlog operation runs, Then it fails closed with 503 and no Git fallback.
- **verification:** go/edpdata tests and test_on_mode_never_writes_file

### FR-5 — Rollback exports and reconciles DB authority
- **priority:** Must
- **source:** AC-5
- **preconditions:** Writers quiesced
- **trigger:** Rollback to file mode
- **inputs:** tenant; DB rows; projection dir
- **outputs:** file projections match DB, including pruning
- **errors:** export id mismatch; missing DSN
- **auth:** Operator/admin command
- **idempotency:** Overwrite/idempotent export
- **data_rules:** Validate data.id before write; Prune projections absent from DB when requested
- **edge_cases:** deleted DB row; corrupt row id; path traversal tenant
- **acceptance:** Given DB authority, When operators quiesce writers and run export with prune and parity, Then files match DB before mode off.
- **verification:** backlog_db_export.py and test_export_write_skip_overwrite


## 8. Operation matrix
| Mode | Operation | Scope | Actor | Expected result | Error |
|---|---|---|---|---|---|
| on | read/list | allowlisted | worker | DB rows authoritative | BACKLOG_DB_UNAVAILABLE |
| on | write/delete | allowlisted | worker | edpsvc write/delete; no file write | BACKLOG_DB_UNAVAILABLE |
| on | read/write | unlisted | worker | file mode | none |
| off | read/write | any | worker | file mode | none |
| on | backfill/parity/export | allowlisted | operator | DB sync and evidence | drift/export error |

## 9. Configuration contract
| Name | Default | Precedence | Valid values | Empty behavior | Invalid behavior | Startup validation |
|---|---|---|---|---|---|---|
| PF_BACKLOG_DB | on | env > config/env-flags.json > on | off,on,dual,shadow | on | BACKLOG_DB_MODE_INVALID | gate1/precheck and operation |
| PF_BACKLOG_DB_SCOPES | product_forge,ProductForge-Dashboard | env > config/env-flags.json > default | comma-separated scope keys | BACKLOG_DB_SCOPES_EMPTY when on | no match = file authority | operation |

## 10. Non-functional requirements
- DB point-read p95 <= 50 ms (bench-t1.json)
- DB API p95 <= max(file p95*1.25,150 ms)
- Parity zero drift for PF-SB
- No cross-tenant reads without tenant context

## 11. Data lifecycle
- Backfill upserts by (tenant_id,id)
- Delete is tenant-scoped
- Export with --prune removes projections absent from DB
- Legacy duplicate IDs are preserved per tenant
- 0023 marks legacy duplicates and enforces new global-ID uniqueness for non-legacy rows.

## 12. Compatibility
- Existing /backlog routes unchanged
- Old binary must stop before composite PK rollout
- 0021/0022 are ordered migrations

## 13. Rollback behavior
- Quiesce writers
- Run export --prune
- Run parity
- Set PF_BACKLOG_DB=off
- Restart file-mode writers

## 14. Observability
- edp_backlog_authority_* metrics
- BACKLOG_DB_* error codes with tenant/reason
- export/parity command output evidence
