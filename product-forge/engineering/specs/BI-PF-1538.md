## 7. Functional requirements
### FR-1 — Inject design and functional-spec mandates
- **priority:** P0
- **source:** BI-PF-1538
- **preconditions:** Implementation/design work is underway for a backlog item.
- **trigger:** A design or specification agent builds its prompt.
- **inputs:** Backlog item; Design template
- **outputs:** Prompt containing five design mandates
- **errors:** Missing mandate blocks Gate 1
- **auth:** Prompt assembly only
- **idempotency:** Prompt generation is read-only
- **data_rules:** All five mandates are present in the assembled prompt
- **edge_cases:** Spec agents only
- **acceptance:** Given a design agent run, when the prompt is assembled, then all five design mandates are present.
- **verification:** pytest tests/test_implementation_controls.py

### FR-2 — Inject implementation mandates into code prompts
- **priority:** P0
- **source:** BI-PF-1538
- **preconditions:** Implementation/design work is underway for a backlog item.
- **trigger:** Implement or fix agent builds its prompt.
- **inputs:** Backlog item; Control matrix
- **outputs:** Prompt containing five implementation mandates and control contract
- **errors:** No controls -> prompt instructs STOP
- **auth:** Prompt assembly only
- **idempotency:** Prompt generation is read-only
- **data_rules:** Mandates outrank speed and require Delivery Complete
- **edge_cases:** Code-writing agents only
- **acceptance:** Given an implement agent run, when the prompt is assembled, then the five implementation mandates and item controls are present.
- **verification:** pytest tests/test_implementation_controls.py::test_control_block_tells_implementer_to_stop_without_matrix

### FR-3 — Validate implementation controls
- **priority:** P0
- **source:** BI-PF-1538
- **preconditions:** Implementation/design work is underway for a backlog item.
- **trigger:** Readiness check runs before code or on final diff.
- **inputs:** design_pack.implementation_controls; Repo tree
- **outputs:** Machine-readable problems JSON
- **errors:** Exit 1 on missing, dead or invalid control
- **auth:** Tooling only
- **idempotency:** Idempotent inspection
- **data_rules:** Required control kinds and AC coverage are enforced
- **edge_cases:** Missing config; Missing symbol path
- **acceptance:** Given a matrix missing a negative test, when the checker runs, then it fails with a concrete problem.
- **verification:** pytest tests/test_implementation_controls.py

### FR-4 — Write design pack through API
- **priority:** P0
- **source:** BI-PF-1538
- **preconditions:** Implementation/design work is underway for a backlog item.
- **trigger:** Operator submits a design pack.
- **inputs:** design_pack object; expected_revision
- **outputs:** Updated backlog item
- **errors:** VALIDATION_FAILED or NOT_FOUND
- **auth:** Operator role required
- **idempotency:** Revision guard prevents lost updates
- **data_rules:** design_pack persisted by core.backlog.update
- **edge_cases:** Wrong revision; Malformed pack
- **acceptance:** Given a valid design pack, when posted to the design-pack endpoint, then the item stores it.
- **verification:** live API call on BI-PF-1538; api/openapi.json

### FR-5 — Enforce Gate 1 and Gate 2.5 control coverage
- **priority:** P0
- **source:** BI-PF-1538
- **preconditions:** Implementation/design work is underway for a backlog item.
- **trigger:** Gate 1 or diff review runs.
- **inputs:** Item; Diff
- **outputs:** Findings and block/pass decision
- **errors:** Fail closed on missing controls
- **auth:** Review tooling only
- **idempotency:** Review evidence append-only
- **data_rules:** Gate 1 requires controls for items created from 2026-11-16
- **edge_cases:** Historical item
- **acceptance:** Given a new item without controls, when Gate 1 runs, then it fails.
- **verification:** scripts/dev/design_pack.py; scripts/dev/architect_review.py

### FR-6 — Require RCCA for escaped defects
- **priority:** P0
- **source:** BI-PF-1538
- **preconditions:** Implementation/design work is underway for a backlog item.
- **trigger:** A defect escapes a passing gate.
- **inputs:** Defect evidence
- **outputs:** RCCA and linked backlog item
- **errors:** No silent cross-PR fix
- **auth:** Process owner
- **idempotency:** One RCCA per escaped defect
- **data_rules:** New backlog item captures missing control or test
- **edge_cases:** Duplicate defect
- **acceptance:** Given an escaped defect, when closure is attempted, then RCCA and a linked item are required.
- **verification:** docs/IMPLEMENTATION-CONTROLS-DESIGN.md
