# Functional Spec — BI-PF-1548 — Dev-Ex & CI: Fast-tier PR gate with 1-hr scheduled full sweep and atomic item finalization

- **Version:** 1
- **Status:** in_progress
- **Owner:** developer
- **Source:** BI-PF-1548
- **Functional SHA:** pending
- **Linked design:** engineering/design/BI-PF-1548.md

## 1. Outcome
Backlog item turnaround time drops from ~39 min to ~16 min without compromising enterprise-grade software quality. PR merge gate executes fast-tier precheck in under 1 minute; full suite runs continuously on a 1-hour schedule on `develop` with automated issue logging; design pack verification is diff-scoped; item finalization is bundled in a single CLI command.

## 2. Actors
- **Developer / Agent:** Runs local fast precheck and atomic item finalization.
- **GitHub Actions (PR Gate):** Runs fast-tier diff-scoped precheck on PR branches to unblock swift merging.
- **GitHub Actions (Scheduled Sweep):** Runs full precheck suite on `develop` every 1 hour.
- **Issue Tracker (`core/issues.py`):** Automatically ingests sweep regressions as `IS-PF-xxxx` findings with paired `BI-PF-xxxx` work items.

## 3. Scope
- `.github/workflows/pf-gates.yml`: Executes `python scripts/dev/precheck.py` on pull requests.
- `.github/workflows/full-sweep.yml`: Executes on schedule cron `0 * * * *` and workflow_dispatch.
- `scripts/dev/design_pack.py`: Implements `--changed` diff scoping and in-memory item reuse.
- `scripts/dev/finalize_item.py`: Implements `--auto-bundle` to atomically populate delivery states, AC verification, final report, and trail events.
- `docs/WORK-EXECUTION-CONTRACT.md` and `AGENTS.md`: Documents Go-by-default execution rule and single-pass spec and design authoring.

## 4. Non-goals
- Modifying production runtime APIs or endpoints.
- Altering database migrations or tenant RLS policies.
- Loosening any quality gate rules or skipping test verification.

## 5. Assumptions and dependencies
- GitHub Actions runners have Python 3.11/3.12 and Go toolchains available.
- `core/issues.py` is capable of recording unattended CI sweep findings with `auto_backlog=True`.

## 6. Domain and glossary
- **Fast-tier precheck:** Diff-scoped precheck running changed-file tests, lint, security scans, and core smoke tests (~30s).
- **Full precheck:** Exhaustive precheck running the complete 800+ test suite and full pipeline validation (~9m).
- **Auto-bundle:** Atomic stamping of all item completion artifacts in one command rather than iterative manual error discovery.

## 7. Functional requirements
- **FR-1:** Pull request CI workflow shall execute `python scripts/dev/precheck.py` without `--full`.
- **FR-2:** Scheduled workflow shall run `python scripts/dev/precheck.py --full` on branch `develop` every 1 hour.
- **FR-3:** Design pack evaluation in fast precheck shall only evaluate changed design packs in the git diff and reuse in-memory items.
- **FR-4:** `finalize_item.py` shall provide `--auto-bundle` to stamp all required delivery and completion fields in one pass.
- **FR-5:** Developer contract docs shall state Go-by-default execution policy and single-pass spec/design authoring.

## 8. Operation matrix
| Mode | Operation | Scope | Actor | Expected result | Error |
|---|---|---|---|---|---|
| CI | PR Gate | PR branch | GitHub Actions | Fast precheck passes in < 1m | Non-zero exit blocks PR |
| CI | Full Sweep | develop | GitHub Actions | Complete suite passes; logs issues on red | Issue raised via core.issues |
| CLI | design-pack --changed | worktree | Developer | Diff-scoped check passes in < 1s | Reports stale/invalid design |
| CLI | finalize_item --auto-bundle | worktree | Developer | Atomic stamping of final report and trail | Fails if AC unverified |

## 9. Configuration contract
| Name | Default | Precedence | Valid values | Empty behavior | Invalid behavior | Startup validation |
|---|---|---|---|---|---|---|
| cron | 0 * * * * | Workflow YAML | Standard cron | Run hourly | Workflow error | GitHub Actions parse |
| --auto-bundle | False | CLI flag | Flag present/absent | Manual mode | Flag error | argparse |

## 10. Non-functional requirements
- PR precheck execution time: < 60 seconds.
- Hourly full sweep execution: unattended, isolated container.
- Zero loss of test coverage or governance enforcement.

## 11. Data lifecycle
- Execution trails and final reports are stored immutably with the backlog item.
- Issues raised by scheduled sweeps are tracked until RCCA and corrective actions close them.

## 12. Compatibility
- Fully backward compatible with existing precheck and finalize_item CLI invocations.

## 13. Rollback behavior
- Reverting workflow and script commits restores previous behaviors immediately.

## 14. Observability
- GitHub Actions logs and `core/issues.py` journal.
