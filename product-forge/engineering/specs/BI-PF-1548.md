# Functional Spec — BI-PF-1548 — Dev-Ex & CI: Fast-tier PR gate with 1-hr scheduled full sweep and atomic item finalization

- **Version:** 1
- **Status:** approved
- **Owner:** developer
- **Source:** BI-PF-1548
- **Functional SHA:** d0cb6d2fb76e
- **Linked design:** engineering/design/BI-PF-1548.md

## 1. Outcome
Backlog item turnaround time drops from ~39 min to ~16 min without compromising enterprise-grade software quality. PR merge gate executes fast-tier precheck in under 1 minute; full suite runs continuously on a 1-hour schedule on develop with automated issue logging; design pack verification is diff-scoped; item finalization is bundled in a single CLI command.

## 2. Actors
- Developer / Agent: Runs local fast precheck and atomic item finalization.
- GitHub Actions (PR Gate): Runs fast-tier diff-scoped precheck on PR branches to unblock swift merging.
- GitHub Actions (Scheduled Sweep): Runs full precheck suite on develop every 1 hour.
- Issue Tracker (core/issues.py): Automatically ingests sweep regressions as IS-PF-xxxx findings with paired BI-PF-xxxx work items.

## 3. Scope
- .github/workflows/pf-gates.yml: Executes python scripts/dev/precheck.py on pull requests.
- .github/workflows/full-sweep.yml: Executes on schedule cron 0 * * * * and workflow_dispatch.
- scripts/dev/design_pack.py: Implements --changed diff scoping and in-memory item reuse.
- scripts/dev/finalize_item.py: Implements --auto-bundle to atomically populate delivery states, AC verification, final report, and trail events.
- docs/WORK-EXECUTION-CONTRACT.md and AGENTS.md: Documents Go-by-default execution rule and single-pass spec and design authoring.

## 4. Non-goals
- Modifying production runtime APIs or endpoints.
- Altering database migrations or tenant RLS policies.
- Loosening any quality gate rules or skipping test verification.

## 5. Assumptions and dependencies
- GitHub Actions runners have Python 3.11/3.12 and Go toolchains available.
- core/issues.py is capable of recording unattended CI sweep findings with auto_backlog=True.
- core.backlog
- core.issues
- core.execution_trail
- scripts/dev/precheck.py

## 6. Domain and glossary
- Fast-tier precheck: Diff-scoped precheck running changed-file tests, lint, security scans, and core smoke tests (~30s).
- Full precheck: Exhaustive precheck running the complete 800+ test suite and full pipeline validation (~9m).
- Auto-bundle: Atomic stamping of all item completion artifacts in one command rather than iterative manual error discovery.

## 7. Functional requirements
### FR-1 — Fast PR Precheck Execution
- **priority:** P0
- **source:** BI-PF-1548
- **preconditions:** Pull request opened or synchronized.
- **trigger:** GitHub Actions workflow triggers on pull_request.
- **inputs:** changed files in PR diff
- **outputs:** fast-tier precheck pass or fail exit status
- **errors:** fast-tier gate failures reported in step logs
- **auth:** tooling only
- **idempotency:** precheck validation is read-only
- **data_rules:** diff-scoped checks on PR diff
- **edge_cases:** no changes in PR diff
- **acceptance:** Given a PR diff, when CI runs, then fast precheck finishes in under 2 minutes.
- **verification:** pytest test-framework/tests/pipeline/test_finalize_item_bundle.py

### FR-2 — Scheduled 1-Hour Full Develop Sweep
- **priority:** P0
- **source:** BI-PF-1548
- **preconditions:** Workflow scheduled or triggered on develop.
- **trigger:** Cron schedule 0 * * * * or workflow_dispatch.
- **inputs:** full repository tree at develop HEAD
- **outputs:** full precheck report and automated issue logging on failure
- **errors:** workflow step failure logs finding via core.issues
- **auth:** tooling only
- **idempotency:** idempotent issue logging by failure signature
- **data_rules:** develop branch full sweep
- **edge_cases:** workflow runner queue delay
- **acceptance:** Given scheduled run on develop, when test fails, then finding is logged in core.issues.
- **verification:** scripts/dev/report_ci_sweep_failure.py

### FR-3 — Diff-Scoped Design Pack Verification
- **priority:** P0
- **source:** BI-PF-1548
- **preconditions:** Precheck fast invokes design_pack.py.
- **trigger:** scripts/dev/design_pack.py --changed --check --fresh.
- **inputs:** git diff vs origin/develop
- **outputs:** changed item design validation in under 1 second
- **errors:** invalid or stale design pack flagged
- **auth:** tooling only
- **idempotency:** pure read-only inspection
- **data_rules:** evaluate only changed engineering/design/*.md files
- **edge_cases:** no design files changed in commit
- **acceptance:** Given git diff, when design pack runs with --changed, then execution takes < 1 second.
- **verification:** pytest test-framework/tests/test_design_pack.py

### FR-4 — Atomic Item Finalization
- **priority:** P0
- **source:** BI-PF-1548
- **preconditions:** Item ready for completion with tests passing.
- **trigger:** scripts/dev/finalize_item.py --auto-bundle --item <ID>.
- **inputs:** backlog item and execution evidence
- **outputs:** stamped delivery states, verified ACs, final report, and trail events
- **errors:** unmet AC blocks finalization
- **auth:** tooling only
- **idempotency:** atomic single-writer write
- **data_rules:** all 5 delivery states marked true
- **edge_cases:** missing test evidence
- **acceptance:** Given completed item, when finalize --auto-bundle runs, then item transitions atomically.
- **verification:** pytest test-framework/tests/pipeline/test_finalize_item_bundle.py

### FR-5 — Contract Documentation and Process Alignment
- **priority:** P0
- **source:** BI-PF-1548
- **preconditions:** Developer reviewing working agreement and EOS.
- **trigger:** Documentation inspection.
- **inputs:** docs/WORK-EXECUTION-CONTRACT.md and AGENTS.md
- **outputs:** clear guidance on Go-by-default execution and single-pass spec authoring
- **errors:** undocumented process variation
- **auth:** public documentation
- **idempotency:** static documentation
- **data_rules:** SSOT aligned with EOS
- **edge_cases:** legacy prompt divergence
- **acceptance:** Given contributor docs, when inspected, then Go-by-default and fast PR precheck are specified.
- **verification:** scripts/dev/docs_fresh_check.py

## 10. Non-functional requirements
- PR precheck execution time: < 60 seconds.
- Hourly full sweep execution: unattended, isolated container.
- Zero loss of test coverage or governance enforcement.

## 11. Data lifecycle
- Execution trails and final reports are stored immutably with the backlog item.
- Issues raised by scheduled sweeps are tracked until RCCA and corrective actions close them.

## 12. Compatibility
