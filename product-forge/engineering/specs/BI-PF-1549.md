## 7. Functional requirements
### FR-1 — deliver.py --item CLI runner
- **priority:** P0
- **source:** BI-PF-1549
- **preconditions:** Local feature branch has code and tests ready.
- **trigger:** Developer or agent invokes scripts/dev/deliver.py --item <ID>.
- **inputs:** item_id; scope; push; delete_branch
- **outputs:** JSON result with merge_sha and status
- **errors:** Rejects develop/main branch with RuntimeError.
- **auth:** tooling only
- **idempotency:** Idempotent delivery execution
- **data_rules:** One delivery per item
- **edge_cases:** Invoked on integration branch
- **acceptance:** Given an active feature branch, when deliver_plane_a runs, then it merges and delivers cleanly.
- **verification:** test-framework/tests/pipeline/test_deliver_plane_a.py::test_deliver_cli_help

### FR-2 — Separated commits for reviews and backlog
- **priority:** P0
- **source:** BI-PF-1549
- **preconditions:** Working tree has unstaged review or backlog changes.
- **trigger:** deliver_plane_a inspects git status.
- **inputs:** git status output
- **outputs:** Separate git commits for reviews and backlog
- **errors:** Pre-commit hook violation
- **auth:** tooling only
- **idempotency:** Safe if already committed
- **data_rules:** No mixed commits
- **edge_cases:** docs/README.md modified by pre-commit hook
- **acceptance:** Given review and backlog diffs, when staged, then they are committed in separate commits.
- **verification:** test-framework/tests/pipeline/test_deliver_plane_a.py::test_deliver_plane_a_signature

### FR-3 — Pre-merge sync and audit validation
- **priority:** P0
- **source:** BI-PF-1549
- **preconditions:** All commits staged on feature branch.
- **trigger:** deliver_plane_a initiates verification.
- **inputs:** sync_develop.py; wired_audit.py
- **outputs:** Verification returncode 0
- **errors:** Audit or sync failure aborts before checkout
- **auth:** tooling only
- **idempotency:** Read-only audit verification
- **data_rules:** Zero unwired modules
- **edge_cases:** Remote divergence
- **acceptance:** Given unmerged remote changes, when sync runs, then it folds develop in cleanly.
- **verification:** test-framework/tests/pipeline/test_deliver_plane_a.py::test_deliver_plane_a_signature

### FR-4 — Controlled merge, push, and delivery provenance
- **priority:** P0
- **source:** BI-PF-1549
- **preconditions:** Verification green and working tree clean.
- **trigger:** deliver_plane_a switches to develop.
- **inputs:** target_branch; feature_branch
- **outputs:** Merge commit on develop, pushed to remote, links.delivery updated
- **errors:** Push rejection
- **auth:** tooling only
- **idempotency:** Idempotent merge recording
- **data_rules:** Delivery provenance stamped in backlog
- **edge_cases:** Local branch cleanup error
- **acceptance:** Given clean merge, when pushed, then links.delivery is stamped on the item.
- **verification:** test-framework/tests/pipeline/test_deliver_plane_a.py::test_deliver_plane_a_signature

### FR-5 — Finalizer --deliver alias
- **priority:** P0
- **source:** BI-PF-1549
- **preconditions:** finalize_item.py invoked with --deliver.
- **trigger:** CLI execution of finalize_item.py.
- **inputs:** --item; --deliver
- **outputs:** Delegation to deliver_plane_a
- **errors:** Delivery failure returns exit code 1
- **auth:** tooling only
- **idempotency:** Idempotent delegation
- **data_rules:** Same outcome as deliver.py
- **edge_cases:** Auto-bundle not passed
- **acceptance:** Given --deliver flag, when finalize_item runs, then it delegates to deliver_plane_a.
- **verification:** test-framework/tests/pipeline/test_deliver_plane_a.py::test_finalize_item_cli_help
