## 7. Functional requirements
### FR-1 — Unified datastore.MemoryRepository implementation in go/dualvec
- **priority:** P0
- **source:** BI-PF-1552
- **preconditions:** Caller initializes dualvec.Config with either SQLite or PostgreSQL DSN.
- **trigger:** Application or pipeline stage calls Put, Get, Search, or Delete.
- **inputs:** MemoryEntry or MemoryScope with query text, vector, tenant, project, and ACL
- **outputs:** Stored MemoryEntry or ranked list of MemoryEntry hits
- **errors:** Validation error on dimension mismatch, storage error on DB down
- **auth:** Server-side principal check; private entries restricted to owner
- **idempotency:** Put with identical ID updates the record idempotently
- **data_rules:** Primary key on id; dimension must strictly match 1536
- **edge_cases:** Zero vector embedding; empty search query; special chars
- **acceptance:** Given valid memory entries, when Put or Search is invoked, then correct entries are stored and retrieved.
- **verification:** go test -v ./go/dualvec/... -run TestSqliteMemoryStoreConformance

### FR-2 — Zero-CGO pure-Go embedded SQLite vector store for PF-SB and local products
- **priority:** P0
- **source:** BI-PF-1552
- **preconditions:** DSN starts with sqlite://, file:, or is a local path.
- **trigger:** dualvec.New creates SqliteMemoryStore.
- **inputs:** SQLite connection string and dimension
- **outputs:** SqliteMemoryStore implementing MemoryRepository
- **errors:** ErrStorageUnavailable on file access errors
- **auth:** Enforced in query predicate before results returned
- **idempotency:** CREATE TABLE IF NOT EXISTS on startup is idempotent
- **data_rules:** Packed 32-bit little-endian float blob serialization
- **edge_cases:** File lock contention; concurrent read/write transactions
- **acceptance:** Given SQLite DSN, when dualvec.New is called, then pure-Go SQLite store runs without CGO.
- **verification:** go test -v ./go/dualvec/... -run TestEngineDetection

### FR-3 — PostgreSQL pgvector adapter for enterprise cloud SaaS and PF-GP
- **priority:** P0
- **source:** BI-PF-1552
- **preconditions:** DSN starts with postgres:// or postgresql://.
- **trigger:** dualvec.New creates PgMemoryStore.
- **inputs:** PostgreSQL DSN and tenant bound connection
- **outputs:** PgMemoryStore wrapping edpdata.MemoryStore
- **errors:** Connection failure returns ErrStorageUnavailable
- **auth:** PostgreSQL RLS with restricted application role pf_app_user
- **idempotency:** Upsert on memory table is idempotent
- **data_rules:** GIN lexical indexing and pgvector HNSW cosine ranking
- **edge_cases:** pgvector extension missing; RLS policy violations
- **acceptance:** Given Postgres DSN, when dualvec.New is called, then pgvector backend is wired with RLS.
- **verification:** go test -v ./go/edpsvc/... -run TestServer_Memory

### FR-4 — Strict multi-tenant, project, and ACL privacy isolation
- **priority:** P0
- **source:** BI-PF-1552
- **preconditions:** Memory entries are stored across multiple tenants, projects, and users.
- **trigger:** Search is invoked with MemoryScope.
- **inputs:** MemoryScope containing TenantID, Project, User, ACL, and Kinds
- **outputs:** Hits filtered strictly to the caller tenant, project, and ACL
- **errors:** Missing TenantID returns error
- **auth:** Caller user can only access private entries owned by them
- **idempotency:** Search is read-only and idempotent
- **data_rules:** Cross-tenant data must never appear in query results
- **edge_cases:** User impersonation attempt; cross-project query
- **acceptance:** Given multiple tenants, when tenant A queries, then zero tenant B rows are returned.
- **verification:** go test -v ./go/dualvec/... -run TestNegativeLeakageIsolation
