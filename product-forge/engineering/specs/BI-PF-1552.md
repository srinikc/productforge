## 7. Functional requirements
### FR-1 — Dual-engine MemoryRepository adapter interface
- **priority:** Must
- **source:** AC-1
- **preconditions:** Memory repository configuration provided
- **trigger:** Initialization of storage repository via DSN dispatch
- **inputs:** PF_MEMORY_DSN connection string
- **outputs:** Configured MemoryRepository instance
- **errors:** ERR_INVALID_DSN; ERR_BACKEND_UNAVAILABLE
- **auth:** Internal service authentication
- **idempotency:** Safe to initialize repeatedly
- **data_rules:** Valid DSN format; SQLite or PostgreSQL schema compliance
- **edge_cases:** Empty DSN defaults to embedded SQLite; Unreachable DB returns error
- **acceptance:** Given valid SQLite or Postgres DSN, When repository initializes, Then MemoryRepository is configured and operational.
- **verification:** go test ./go/dualvec -v

### FR-2 — Embedded SQLite vector store for zero-dependency local sovereign deployment
- **priority:** Must
- **source:** AC-2
- **preconditions:** Local filesystem writable
- **trigger:** Local SQLite DSN dispatch
- **inputs:** Memory entries with vector embeddings
- **outputs:** Persisted SQLite records and cosine similarity matches
- **errors:** ERR_SQLITE_IO_FAILED; ERR_INVALID_EMBEDDING_DIM
- **auth:** Local file system permissions
- **idempotency:** Upserts are idempotent by entry key
- **data_rules:** 1536-dimensional float vector packing; Strict local file isolation
- **edge_cases:** Database file locked handles busy timeout gracefully
- **acceptance:** Given embedded deployment, When vector entries are stored and queried, Then cosine similarity retrieval succeeds with zero external daemons.
- **verification:** go test ./go/dualvec -run TestSQLiteStore

### FR-3 — Enterprise PostgreSQL pgvector store with multi-tenant row-level security
- **priority:** Must
- **source:** AC-3
- **preconditions:** PostgreSQL database accessible with pgvector
- **trigger:** Postgres connection string provided in PF_MEMORY_DSN
- **inputs:** Tenant ID, memory entries, vector embeddings
- **outputs:** Tenant-isolated memory records and vector query results
- **errors:** ERR_PG_CONNECTION_FAILED; ERR_TENANT_VIOLATION
- **auth:** Tenant context and database authentication
- **idempotency:** ON CONFLICT DO UPDATE upsert semantics
- **data_rules:** Multi-tenant RLS scoping; 1536-dim vector indexing
- **edge_cases:** Cross-tenant query returns empty without data leakage
- **acceptance:** Given multi-tenant enterprise runtime, When querying across tenant boundaries, Then zero cross-tenant memory leakage occurs.
- **verification:** go test ./go/dualvec -run TestPGStore

### FR-4 — Shared memory conformance test suite across storage backends
- **priority:** Must
- **source:** AC-4
- **preconditions:** Both storage backends initialized
- **trigger:** Execution of shared test matrix
- **inputs:** 8 canonical memory record types
- **outputs:** Test execution report confirming parity
- **errors:** ERR_CONFORMANCE_MISMATCH
- **auth:** Test runner execution context
- **idempotency:** Tests isolate temp tables and tear down clean
- **data_rules:** Equal semantic recall between SQLite and Postgres
- **edge_cases:** Negative vector bounds and NaN values rejected fail-closed
- **acceptance:** Given shared conformance suite, When run against SQLite and PostgreSQL, Then all 8 memory types and ACL checks pass identically.
- **verification:** go test ./go/dualvec -v
