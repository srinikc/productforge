## 7. Functional requirements
### FR-1 — SPA asset compilation and content-hash integrity verification
- **priority:** P0
- **source:** BI-PF-1553
- **preconditions:** Web console source assets are compiled into distribution directory.
- **trigger:** Build pipeline executes web console asset bundling.
- **inputs:** source_dir; output_dist_dir
- **outputs:** content_hashed_assets; checksums.txt manifest
- **errors:** ASSET_INTEGRITY_MISMATCH; EMBED_DIR_NOT_FOUND
- **auth:** build pipeline only
- **idempotency:** deterministic content hashing
- **data_rules:** all static chunks carry sha256 checksums
- **edge_cases:** zero-byte asset files; deeply nested asset directories
- **acceptance:** Given compiled web console assets, when the build pipeline packages them, content hashing and checksum manifest verify 100% integrity.; Go server startup validates embedded asset SHA256 hashes against embedded checksums.txt manifest before serving.
- **verification:** pytest test-framework/tests/pipeline/test_web_console_packaging.py::test_web_console_build_and_integrity

### FR-2 — Go embedded platform server with gzip, caching, and SPA fallback
- **priority:** P0
- **source:** BI-PF-1553
- **preconditions:** Platform server Go binary built with embedded asset filesystem.
- **trigger:** Inbound HTTP GET request for web console routes.
- **inputs:** http.Request
- **outputs:** http.Response with embedded asset or index.html
- **errors:** 404 for missing static asset under /assets/; 500 for internal read error
- **auth:** unauthenticated public web assets; downstream session auth
- **idempotency:** read-only immutable embedded filesystem
- **data_rules:** Cache-Control immutable for hashed assets; no-cache for index.html
- **edge_cases:** client does not accept gzip; client requests non-existent asset path
- **acceptance:** Given an inbound HTTP request, Go server serves embedded assets with transparent gzip, immutable caching, and client-side SPA fallback.; Unmatched /api/* requests return 404 JSON and never fall back to index.html.
- **verification:** pytest test-framework/tests/pipeline/test_web_console_packaging.py::test_go_embedded_server_headers_and_gzip

### FR-3 — Fail-closed customer package IP protection guard
- **priority:** P0
- **source:** BI-PF-1553
- **preconditions:** Customer edition package assembled.
- **trigger:** Package verification executes during packaging build.
- **inputs:** package_output_dir; edition
- **outputs:** validation result with unmet list
- **errors:** RAW_FRONTEND_SOURCE_DETECTED; NODE_MODULES_DETECTED
- **auth:** packaging pipeline authority
- **idempotency:** read-only filesystem scan
- **data_rules:** zero .ts, .tsx, .jsx, or node_modules/ allowed in customer editions
- **edge_cases:** nested node_modules inside dependencies; hidden .tsx files
- **acceptance:** Given customer edition distribution, validator fails closed if any raw frontend source or node_modules is present.
- **verification:** pytest test-framework/tests/pipeline/test_web_console_packaging.py::test_customer_package_zero_nodejs_and_raw_sources

## 10. Non-functional requirements
- deterministic: build toolchain pinned to Node.js 20 LTS, frozen lockfile (npm ci / pnpm --frozen-lockfile), and SOURCE_DATE_EPOCH=0 for reproducible content hashing
- sub-millisecond static response: in-memory embed.FS static delivery
- zero runtime Node.js: runtime platform binary requires no Node.js or npm packages

## 11. Data lifecycle
build-time compiled asset bundle; immutable read-only runtime

## 12. Compatibility
additive embedded web console handler

## 13. Rollback behavior
Serve web console from external static directory via configuration flag env:PF_CONSOLE_STATIC_DIR without binary rebuild.

## 14. Observability
