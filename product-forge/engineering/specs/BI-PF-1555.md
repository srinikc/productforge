## 1. Outcome
Plane A (Product Forge platform itself) turnkey cloud provisioning bundle operational: official Helm chart, multi-cloud AWS/GCP Terraform modules, and deployment runner passing post-deploy health check.

## 2. Actors
- Platform DevOps Engineer
- Cloud Infrastructure Operator
- Enterprise Deployment Administrator

## 3. Scope
- deploy/plane-a/helm/product-forge/
- deploy/plane-a/terraform/aws/
- deploy/plane-a/terraform/gcp/
- scripts/dev/plane_a_deployer.py
- scripts/dev/deploy_plane_a.py
- test-framework/tests/pipeline/test_plane_a_deployer.py

## 4. Non-goals
- Plane B customer application deployments
- Public DNS registration or commercial TLS certificate authority management
- Bare-metal non-Kubernetes server deployments

## 5. Assumptions and dependencies
- Target cloud platforms are standard managed Kubernetes (AWS EKS, GCP GKE)
- PostgreSQL database requires pgvector extension and multi-tenant RLS
- Object storage is S3-compatible (AWS S3, GCS S3 interoperability, MinIO)
- ADR-0001: Containerized platform runtime
- BI-PF-1307: Object storage abstractions
- BI-PF-1309: Multi-tenant PostgreSQL database with pgvector

## 6. Domain and glossary
- Plane A: Product Forge engineering factory platform runtime
- Helm Chart: Kubernetes package standard for platform deployment
- Terraform: Infrastructure as Code for multi-cloud provisioning

## 7. Functional requirements
### FR-1 — Turnkey Production Helm Chart Packaging Platform Stack
- **priority:** Must
- **source:** AC-1
- **preconditions:** Kubernetes cluster accessible via kubeconfig
- **trigger:** Execution of helm install/upgrade or deployer script
- **inputs:** values.yaml overrides; target namespace
- **outputs:** Core API pods, PostgreSQL StatefulSet with pgvector, MinIO, and Services
- **errors:** ERR_HELM_SYNTAX_INVALID; ERR_PGVECTOR_UNAVAILABLE
- **auth:** Kubernetes RBAC cluster administrator
- **idempotency:** Declarative Helm release management ensures idempotent upgrades
- **data_rules:** Persistent volume retention policy Retain on stateful storage; Non-root security context
- **edge_cases:** Existing release upgrade; Missing mandatory secrets; Pre-existing volume re-attachment
- **acceptance:** Given a target Kubernetes cluster, When the Helm chart is applied, Then PostgreSQL with pgvector, object store, and core API pods are deployed healthy.; Given persistent volumes, When pods restart or uninstalled, Then volume retention policy Retain prevents data destruction.
- **verification:** test-framework/tests/pipeline/test_plane_a_deployer.py::test_helm_chart_manifest_generation

### FR-2 — Multi-Cloud Terraform Modules for Managed Kubernetes and HA Database
- **priority:** Must
- **source:** AC-2
- **preconditions:** Valid AWS IAM or GCP Service Account credentials
- **trigger:** Execution of terraform apply with provider selection
- **inputs:** provider: aws or gcp; cluster_name; region; node_count; db_instance_class
- **outputs:** Provisioned VPC, managed Kubernetes cluster (EKS/GKE), and Multi-AZ / Regional HA PostgreSQL
- **errors:** ERR_CREDENTIALS_MISSING; ERR_QUOTA_EXCEEDED
- **auth:** Cloud provider IAM credentials
- **idempotency:** Declarative Terraform state guarantees zero duplicate infrastructure resources
- **data_rules:** Database multi-az or regional replication enabled; Automated backups configured
- **edge_cases:** Cloud quota limits exceeded; Invalid subnet CIDR blocks; IAM permission denied
- **acceptance:** Given valid AWS credentials, When Terraform module is executed, Then EKS cluster with node group and Multi-AZ RDS instance are provisioned.; Given valid GCP credentials, When Terraform module is executed, Then GKE cluster and Regional HA Cloud SQL instance are provisioned.
- **verification:** test-framework/tests/pipeline/test_plane_a_deployer.py::test_terraform_module_definitions

### FR-3 — Automated Single-Command Deployer with Health Check and Rollback
- **priority:** Must
- **source:** AC-3
- **preconditions:** Target cloud credentials and Kubernetes environment configured
- **trigger:** Invocation of python scripts/dev/deploy_plane_a.py
- **inputs:** --provider <aws|gcp|local>; --dry-run; --plan
- **outputs:** Deployed platform verified healthy with HTTP 200 on health probes within SLA
- **errors:** ERR_HEALTH_CHECK_TIMEOUT; ERR_DEPLOYMENT_FAILED
- **auth:** Platform operator credentials
- **idempotency:** Re-running deployer verifies existing healthy deployment without mutation
- **data_rules:** Health timeout threshold 120s; Structured JSON diagnostic logs
- **edge_cases:** Probe timeout triggers non-destructive rollback; Dry run outputs plan without side-effects
- **acceptance:** Given configured infrastructure, When deployer is run, Then infrastructure is verified and health probe succeeds in under 10 minutes.; Given a failing health probe, When timeout is reached, Then deployer triggers non-destructive helm rollback without database teardown.
- **verification:** test-framework/tests/pipeline/test_plane_a_deployer.py::test_plane_a_deployer_cli


## 8. Operation matrix
| Mode | Operation | Scope | Actor | Expected result | Error |
|---|---|---|---|---|---|
| plan | validate_manifests | local/cloud | operator | Plan summary generated without mutating cluster | ERR_VALIDATION_FAILED |
| deploy | apply_stack | target_cluster | deployer | Platform stack deployed and verified healthy | ERR_DEPLOYMENT_FAILED |
| rollback | helm_rollback | kubernetes_release | deployer | Reinstated prior healthy revision preserving volumes | ERR_ROLLBACK_FAILED |

| Name | Default | Precedence | Valid values | Empty behavior | Invalid behavior | Startup validation |
|---|---|---|---|---|---|---|
| PF_DEPLOY_PROVIDER | local | cli flag > env > config file | local,aws,gcp | defaults to local | ERR_INVALID_PROVIDER | deployer argument validation |
| POSTGRES_HOST |  | helm values.yaml > configmap default | valid DNS hostname or IP | uses internal StatefulSet service | connection failure | pod readiness probe |

## 10. Non-functional requirements
- Warm cluster deployment completed within 10 minutes
- Cold infrastructure provisioning within 25 minutes
- Zero downtime rolling updates via maxSurge 1, maxUnavailable 0

## 11. Data lifecycle
- PersistentVolumeClaims retain data across pod restarts and Helm uninstalls
- Database snapshots taken prior to major platform upgrades

## 12. Compatibility
- Kubernetes 1.28+
- PostgreSQL 15+ with pgvector
- Terraform 1.5+

## 13. Rollback behavior
- Automated helm rollback to prior revision on health check failure
- Database schema changes are strictly backward-compatible

## 14. Observability
- Structured JSON logging with timestamps and phase markers
- Prometheus scrape annotations on service manifests
