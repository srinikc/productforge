## 1. Outcome
Plane A (Product Forge platform itself) turnkey cloud provisioning bundle operational: an official production Helm chart (`deploy/plane-a/helm/product-forge/`) packaging Product Forge core API, EDP service, PostgreSQL with pgvector, and object storage; comprehensive Terraform modules (`deploy/plane-a/terraform/`) for AWS (EKS + RDS) and GCP (GKE + Cloud SQL); and a single-command deployment runner (`core/plane_a_deployer.py` and `scripts/dev/deploy_plane_a.py`) that provisions cloud infrastructure, deploys the Helm chart, and passes automated post-deploy health checks in under 10 minutes.

- Continuous Delivery Automation Worker

## 4. Non-goals
- Plane B client application deployments (governed separately by `core/deploy_providers.py`).
- Public DNS and domain certificate acquisition (pluggable through standard cert-manager / external-dns).
- Bare-metal hardware provisioning (cloud native Kubernetes targets only).

## 5. Assumptions and dependencies
- Target cloud platforms: AWS (EKS, VPC, RDS PostgreSQL) and GCP (GKE, VPC, Cloud SQL PostgreSQL).
- Local development & CI verification target: Minikube / Kind / Docker-Compose emulation.
- Database requirement: PostgreSQL 15+ with `pgvector` extension enabled.
- Storage requirement: S3-compatible object storage (AWS S3, Google Cloud Storage via S3 interoperability, or bundled MinIO).
- ADR-0001 / BI-PF-0388: Containerized Plane A platform execution.

## 6. Domain and glossary
- Plane A: The Product Forge engineering factory platform itself.
- Helm Chart: Package format for Kubernetes resources defining Product Forge services, dependencies, and configuration.
- Terraform Module: Infrastructure-as-code definitions automating VPC, Kubernetes cluster, and managed database provisioning.
- Single-Command Provisioner: Automated orchestration script coordinating plan, apply, helm install, and health check.
- Health Check: Post-deployment verification querying `/api/v1/health` and database connectivity to validate system readiness.

## 7. Functional requirements
### FR-1 — Turnkey Production Helm Chart
- **priority:** P0
- **source:** BI-PF-1555 (AC-1)
- **preconditions:** Kubernetes cluster accessible via kubeconfig.
- **trigger:** Execution of `helm install product-forge` or one-click provisioner script.
- **inputs:** Helm values override (`values.yaml`), release namespace.
- **outputs:** Deployed Product Forge API deployment, EDP service, PostgreSQL with pgvector, object store, Service, and ConfigMap resources.
- **errors:** Validation failure on missing mandatory secret or invalid image tag.
- **auth:** Kubernetes RBAC / cluster administrator.
- **idempotency:** Helm upgrades are idempotent with declarative state management.

### FR-2 — Multi-Cloud Terraform Infrastructure Modules
- **priority:** P0
- **source:** BI-PF-1555 (AC-2)
- **preconditions:** Valid cloud provider credentials (AWS IAM / GCP Service Account).
- **trigger:** Execution of `terraform apply` or provisioner script with provider selection.
- **inputs:** Cloud provider (`aws` or `gcp`), cluster name, region, node count, DB instance class.
- **outputs:** Provisioned VPC, subnets, Kubernetes cluster, and PostgreSQL database instance.
- **errors:** Cloud quota limits or permission denial causes fail-fast exit.
- **auth:** Cloud provider IAM credentials.
- **idempotency:** Declarative Terraform state prevents duplicate resources.

### FR-3 — Automated Single-Command Deployer & Health Verification
- **priority:** P0
- **source:** BI-PF-1555 (AC-3)
- **preconditions:** Configured deployment target and environment variables.
- **trigger:** Invocation of `python scripts/dev/deploy_plane_a.py --provider <aws|gcp|local>`.
- **inputs:** Target provider, configuration parameters, dry-run flag.
- **outputs:** Complete deployed platform verified healthy with HTTP 200 on health probes in under 10 minutes.
- **errors:** Health probe timeout or failed pod readiness aborts deployment with actionable diagnostics.
- **auth:** Platform operator credentials.
- **idempotency:** Rerunning deployment script verifies existing healthy deployment without disruption.

## 8. Acceptance Criteria
- **AC-1:** Helm chart deploys complete Product Forge platform stack including PostgreSQL with pgvector, object store, and core API pods with persistent volume retention.
- **AC-2:** Terraform module automates cloud VPC, managed Kubernetes cluster, and HA database provisioning across AWS and GCP providers.
- **AC-3:** Single command deployment script provisions infrastructure, deploys Helm chart, and passes automated post-deploy health check in under 10 minutes on warm clusters (25 minutes for cold cloud cluster provisioning), with dry-run support.
