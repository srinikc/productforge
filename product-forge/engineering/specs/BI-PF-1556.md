# Functional Spec — BI-PF-1556 — Automated Deployment Rollback Orchestration: trigger instant rollback and record evidence on failed post-deploy smoke tests

- **Version:** 1

## 1. Outcome
Automated post-deployment smoke test runner dispatches non-destructive service-scoped rollback within 30 seconds upon failed health probes, preventing broken platform revisions from remaining online.

## 2. Actors
- Platform DevOps Engineer
- Continuous Deployment Pipeline
- Site Reliability Engineer

## 3. Scope
- scripts/dev/rollback_orchestrator.py
- core/release_manager.py
- test-framework/tests/deployment/test_rollback_orchestrator.py

## 4. Non-goals
- Destructive dropping or truncating of production database tables
- Disrupting unrelated platform services outside the failing revision
- Bypassing audit logging on administrative overrides

## 5. Assumptions and dependencies
- Deployments maintain immutable service revision snapshots
- Post-deployment smoke probes authenticate using tenant-scoped tokens
- Database migrations follow expand-contract without destructive drops in deployment path
- core/release_manager.py
- FastAPI platform service
- PostgreSQL 16

## 6. Domain and glossary
- Plane A Deployment Automation
- Fail-Closed Deployment Health Verification
- Non-Destructive Revision Rollback

## 7. Functional requirements
### FR-1 — Post-deployment smoke test runner executes automated health, database connectivity, and core API verification immediately after deployment.
- **priority:** Must
- **source:** AC-1
- **preconditions:** Target deployment revision reachable; Tenant authorization credentials configured
- **trigger:** Post-deployment automation pipeline execution
- **inputs:** deployment_id; health_endpoints; retry_threshold
- **outputs:** Smoke test status report; Rollback execution trace
- **errors:** ERR_SMOKE_PROBE_FAIL; ERR_WATCHDOG_TIMEOUT; ERR_ROLLBACK_DISPATCH_FAIL
- **auth:** Tenant bearer token and admin override token
- **idempotency:** Idempotent smoke checks and bounded revision reversion
- **data_rules:** Expand-contract migration safety; Service-scoped blast radius
- **edge_cases:** Probe timeout exceeding watchdog limit; Transient network errors recovered within retry threshold
- **acceptance:** {'then': 'Deployment passes if all probes succeed, or dispatches fail-closed rollback within 30s if probes fail.', 'when': 'Automated smoke assertions execute against health and tenant endpoints', 'given': 'A newly deployed service revision'}
- **verification:** pytest test-framework/tests/deployment/test_rollback_orchestrator.py

## 8. Operation matrix
| Mode | Operation | Scope | Actor | Expected result | Error |
|---|---|---|---|---|---|
| smoke_test | run_smoke_assertions | target_service_revision | orchestrator | HTTP 200 OK across health, tenant auth, and DB probe endpoints | ERR_SMOKE_PROBE_FAIL |
| rollback | trigger_fail_closed_rollback | failing_service_revision | orchestrator | Target revision reverted to prior release snapshot within 30s | ERR_ROLLBACK_FAILED |
| admin_override | apply_admin_override | pipeline_lock | admin | Admin override token validated and audit log emitted | ERR_UNAUTHORIZED_OVERRIDE |

## 9. Configuration contract
| Name | Default | Precedence | Valid values | Empty behavior | Invalid behavior | Startup validation |
|---|---|---|---|---|---|---|
| retry_threshold | 3 | cli flag > env > default | positive integer | defaults to 3 | validation error | orchestrator init |
| rollback_timeout_seconds | 30 | cli flag > env > default | positive integer | defaults to 30 | validation error | orchestrator init |

## 10. Non-functional requirements
- Automated rollback executes within 30 seconds of probe failure
- Zero data loss during revision reversion
- Watchdog timeout enforces fail-closed abort at 45 seconds

## 11. Data lifecycle
- Evidence ledger entries stored append-only under data/evidence/rollbacks/
- Database schemas retained without modification across application rollbacks

## 12. Compatibility
- Python 3.11+
- FastAPI
- PostgreSQL 16

## 13. Rollback behavior
- Non-destructive reversion to prior release snapshot using core.release_manager
- Expand-contract migrations ensure database compatibility across revisions

## 14. Observability
- Structured JSON logging in data/evidence/rollbacks/
- Prometheus metrics incremented on deployment rollback dispatch
