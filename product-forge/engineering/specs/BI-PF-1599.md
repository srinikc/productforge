## 7. Functional requirements
### FR-1 — Interactive HIL mode halts at review gates awaiting operator decision
- **priority:** Must
- **source:** AC-1
- **preconditions:** Item in progress with gate review pending
- **trigger:** Execution of gate orchestrator in interactive mode
- **inputs:** Item ID, gate name, review findings
- **outputs:** Interactive terminal prompt and operator decision
- **errors:** ERR_INVALID_DECISION; ERR_GATE_TIMEOUT
- **auth:** Local developer / operator session
- **idempotency:** Re-prompting without state mutation is idempotent
- **data_rules:** Strict interactive prompt when mode is interactive
- **edge_cases:** Non-TTY terminal halts with clear prompt error
- **acceptance:** Given interactive mode, When a review gate is encountered, Then execution halts and prompts operator for explicit sign-off.
- **verification:** pytest test-framework/tests/pipeline/test_gate_orchestrator.py -k test_interactive_mode

### FR-2 — Autonomous mode auto-evaluates dispositions and advances gates
- **priority:** Must
- **source:** AC-2
- **preconditions:** Item in progress with advisory findings only
- **trigger:** Execution of gate orchestrator with --mode auto or PF_EXECUTION_MODE=auto
- **inputs:** Item ID, review findings JSON
- **outputs:** Recorded dispositions and advanced gate state
- **errors:** ERR_BLOCKING_FINDING_ABORT
- **auth:** Authorized automated worker token
- **idempotency:** Auto-disposition generation is deterministic
- **data_rules:** Blocking findings fail closed and halt auto mode
- **edge_cases:** Fatal blocking finding stops auto mode and alerts operator
- **acceptance:** Given auto mode with advisory findings, When gates execute, Then dispositions are auto-recorded and gates advance automatically.
- **verification:** pytest test-framework/tests/pipeline/test_gate_orchestrator.py -k test_auto_mode

### FR-3 — Execution mode resolver determines policy from item and environment
- **priority:** Must
- **source:** AC-3
- **preconditions:** Backlog item or environment configuration present
- **trigger:** Invocation of resolve_execution_mode()
- **inputs:** Item execution_mode field, PF_EXECUTION_MODE env var, CLI flag
- **outputs:** Resolved ExecutionMode enum (INTERACTIVE or AUTO)
- **errors:** ERR_INVALID_EXECUTION_MODE
- **auth:** Boundary authorization
- **idempotency:** Pure deterministic resolution
- **data_rules:** CLI flag > item field > env var > default INTERACTIVE
- **edge_cases:** Unrecognized mode string safely defaults to INTERACTIVE
- **acceptance:** Given varying configuration levels, When mode is resolved, Then precedence hierarchy evaluates with safe interactive default.
- **verification:** pytest test-framework/tests/pipeline/test_gate_orchestrator.py -k test_resolve_mode

### FR-4 — End-to-end pipeline gate orchestration and PostgreSQL DB authority
- **priority:** Must
- **source:** AC-4
- **preconditions:** Backlog database running and schema initialized
- **trigger:** Pipeline delivery run
- **inputs:** Item ID, full gate chain
- **outputs:** Gate 0 -> Gate 1.5 -> Gate 1 -> Gate 2.5 -> Gate 2 execution trail
- **errors:** ERR_GATE_FAILURE; ERR_DB_UNAVAILABLE
- **auth:** Admin token for database operations
- **idempotency:** Pipeline steps are re-entrant and record audit trail
- **data_rules:** PF_BACKLOG_DB defaults to 'on' everywhere without downgrade
- **edge_cases:** Database retry on transient failure avoids data corruption
- **acceptance:** Given complete pipeline run, When all gates pass, Then delivery provenance and execution trail are stamped in DB and committed.
- **verification:** pytest test-framework/tests/pipeline/test_gate_orchestrator.py -k test_e2e_pipeline

| Mode | Operation | Scope | Actor | Expected result | Error |
|---|---|---|---|---|---|
| interactive | run_interactive_gate | orchestrator | developer | Prompt shown and decision captured | ERR_INTERACTIVE_HALT |
| auto | run_autonomous_gate | orchestrator | gate_orchestrator | Auto-dispositions applied and gate passed | ERR_AUTO_HALT |

## 9. Configuration contract
| Name | Default | Precedence | Valid values | Empty behavior | Invalid behavior | Startup validation |
|---|---|---|---|---|---|---|
| PF_EXECUTION_MODE | interactive | cli flag > item field > env > default | interactive,auto | defaults to interactive | safe fallback to interactive | gate_orchestrator.validate_mode |
| PF_BACKLOG_DB | on | env > default | on,off | defaults to on | defaults to on | backlog.is_db_enabled |

## 10. Non-functional requirements
- Sub-50ms disposition evaluation and sub-200ms policy engine execution
- Zero data corruption on concurrent ID sequence allocation

## 11. Data lifecycle
- Append-only execution trail persisted in engineering/trails/<ID>.json
- PostgreSQL sequence monotonicity enforced

## 12. Compatibility
- Python 3.10+
- PostgreSQL 14+

## 13. Rollback behavior
- Revert execution mode to interactive to immediately re-enable manual human gate sign-off.

## 14. Observability

- Deterministic Gate 0/1.5/2.5 status reporting
